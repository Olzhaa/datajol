DSA2 Advanced Algorithms: Күрделі алгоритмдер: Dijkstra, union-find, MST, KMP, trie, динамикалық бағдарламалау

DSA1-ден кейінгі қадам: есепті жүйелі шешу тәсілі, sliding window мен prefix sum, hash table-дың ішкі құрылысы, сызықтық сұрыптау мен heapsort, теңгерімді ағаштар, union-find, Dijkstra, minimum spanning tree, greedy, күрделірек DP, KMP және trie. Әр сабақта алгоритмді Python-да өзіңіз жазасыз, тесттер шеткі жағдайларды да, жылдамдықты да тексереді.

Тіркелмей бірінші сабақты бастау Барлық тапсырмалар

1. Алгоритмдік есепті шешу тәсілі

DSA1 курсында құралдарды үйрендіңіз: hash map, екі көрсеткіш, binary search, BFS, DP. Енді сұрақ басқа: жаңа есепті көргенде қайдан бастау керек? Тәжірибелі әзірлеуші бірден код жазбайды. Ол бірнеше қадамнан тұратын тұрақты тәртіппен жүреді.

Бес қадам

  • Шартты оқу. Кіріс не, шығыс не, шектеулер қандай? n ≤ 10⁵ болса, O(n²) өтпейді. Сандар теріс бола ала ма? Бос тізім келуі мүмкін бе?
  • Мысалдар. Берілген мысалды қолмен шешіңіз, сосын өзіңіз шеткі мысал ойлап табыңыз: бос кіріс, бір элемент, барлығы бірдей, ең үлкен мән.
  • Brute force. Алдымен ең қарапайым дұрыс шешімді айтыңыз (кейде жазыңыз). Ол баяу болса да, жауапты тексеретін «эталон» болады.
  • Жақсарту. Brute force-тың қай бөлігі қайталанады? Оны set, dict, сұрыптау, prefix sum немесе heap арқылы жылдамдатуға бола ма?
  • Тексеру. Уақыт пен жад күрделілігін атаңыз, шеткі жағдайларды кодпен өткізіңіз.

Уақыт және жад

Big-O тек уақытқа емес, жадқа да қолданылады. set-ке n элемент жинасаңыз, қосымша жад O(n). n×m DP кестесі O(n·m) жад алады, ал тек алдыңғы қатарды сақтасаңыз, O(m) жеткілікті. Рекурсия да жад жейді: тереңдігі d болса, стекте d кадр тұрады.

Жартылай ашық аралық [l, r)

Python-да range(l, r) және a[l:r] сол жақты қосады, оң жақты қоспайды. Бұл ыңғайлы: ұзындығы r - l, ал [0, k) және [k, n) бір-бірін жаппай, тізімді толық бөледі. Өз функцияларыңызда да осы келісімді ұстаныңыз, сонда «бір артық, бір кем» (off-by-one) қателері азаяды.

from bisect import bisect_left

# Алматыдағы дүкеннің сұрыпталған чек сомалары
checks = [800, 1200, 1200, 2500, 4000, 7300]
# [1000, 4000) аралығындағы чектер саны
lo = bisect_left(checks, 1000)   # 1000-нан кіші емес бірінші индекс: 1
hi = bisect_left(checks, 4000)   # 4000-нан кіші емес бірінші индекс: 4
print(hi - lo)                   # 3 чек: 1200, 1200, 2500

Екі bisect_left шақыруы және hi - lo айырмасы: жартылай ашық аралықтың классикалық үлгісі. Әр сұрау O(log n).

Жиі қателер

  • Шектеулерді оқымай, бірден O(n²) жазу.
  • Циклдің соңғы индексі: range(len(a) - 1) соңғы элементті өткізіп жібереді.
  • Бос кірісті тексермеу: max([]) қате береді.
  • Brute force-пен салыстырмай, жылдам шешімге сеніп қалу.

Сұхбат кезеңдері

Техникалық сұхбат әдетте осылай өтеді: есепті нақтылау сұрақтары (2-3 минут), brute force идеясы, жақсартылған идея және оның күрделілігі, код жазу, мысалмен қолмен «жүгіріп» шығу. Үнсіз отырмаңыз: ойлау барысын дауыстап айту кодтың өзі сияқты бағаланады.

Кеңес: кез келген жылдам шешімді жазғанда brute force нұсқасын қатар ұстаңыз да, кездейсоқ шағын кірістерде екеуін салыстырыңыз. Бұл тестілеудің ең арзан әрі ең сенімді тәсілі.

2. Sliding window және prefix sums

DSA1-де бір өлшемді prefix sum мен «қайталанбайтын символдары бар ең ұзын жол» есебін көрдік. Бұл сабақта екі техниканы жүйелейміз: sliding window (жылжымалы терезе) және prefix sums, оның ішінде екі өлшемді нұсқасы.

Тұрақты өлшемді терезе

Астанадағы автобус паркінде күндік жолаушы саны бар. 7 күндік жылжымалы орташаны есептеу керек. Аңғал тәсіл әр терезені қайта қосады: O(n·k). Ақылды тәсіл: терезе бір қадам оңға жылжығанда, сол жақтан шыққан мәнді алып, оң жақтан кірген мәнді қосамыз. Әр қадам O(1), барлығы O(n).

def moving_sums(a, k):
    if k > len(a):
        return []
    s = sum(a[:k])          # бірінші терезе [0, k)
    out = [s]
    for r in range(k, len(a)):
        s += a[r] - a[r - k]   # a[r] кірді, a[r - k] шықты
        out.append(s)
    return out

print(moving_sums([3, 1, 4, 1, 5], 2))   # [4, 5, 5, 6]

Өзгермелі өлшемді терезе

Екі көрсеткіш l мен r терезенің шекарасы [l, r]. r әрқашан оңға жүреді. Терезе шартты бұзса (мысалы, бірдей символ екі рет кездессе немесе әртүрлі символ саны k-дан асса), l-ді шарт қайта орындалғанша оңға жылжытамыз. Әр көрсеткіш n қадамнан аспайды, сондықтан жалпы O(n). Терезедегі символ санын dict немесе Counter-да ұстаймыз; саны 0-ге түскен кілтті өшіру керек, әйтпесе len қате болады.

Prefix sums: екі өлшем

Бір өлшемде pre[i] = алғашқы i элементтің қосындысы, ал [l, r) аралығы pre[r] - pre[l]. Кофеханалар желісінің кестесін елестетіңіз: жол = филиал, баған = сағат. «2-5 филиалдардың 9-13 сағаттағы түсімі» сияқты көп сұрауға жауап беру үшін P[i][j] = [0, i) × [0, j) тіктөртбұрышының қосындысы деп құрамыз:

P[i + 1][j + 1] = g[i][j] + P[i][j + 1] + P[i + 1][j] - P[i][j]
# [r1, r2) × [c1, c2) қосындысы:
P[r2][c2] - P[r1][c2] - P[r2][c1] + P[r1][c1]

Екі рет алынған бұрыш P[r1][c1] бір рет қайта қосылады (қосу-алу принципі). Кестені құру O(R·C), әр сұрау O(1).

Жиі қателер

  • Терезе өлшемі тізімнен үлкен болғанда (k > n) бос нәтижені ұмыту.
  • Prefix массивін n емес, n + 1 ұзындықта құру керек: pre[0] = 0.
  • Теріс сандар бар тізімде «қосынды ≥ target» үшін sliding window жарамайды: терезені тарылту қосындыны міндетті түрде кемітпейді. Ондай кезде prefix sum + hash map немесе басқа тәсіл керек.
  • Counter-дан нөлге түскен кілтті өшірмеу.
Кеңес: «қатар тұрған элементтер», «ішкі жол», «соңғы k күн» сөздерін көрсеңіз, алдымен sliding window туралы ойлаңыз. «Көп сұрау, аралық қосындысы» деген болса, prefix sum құрыңыз.

3. Hash table ішінен

DSA1-де dict пен set-ті «орташа O(1)» құрал ретінде қолдандық. Бұл сабақта олардың ішінде не болатынын көреміз және өз hash table-ымызды жазамыз.

Hash function және bucket

Hash table: m ұяшықтан (bucket) тұратын массив. Кілтті сақтау үшін hash function оны бүтін санға айналдырады, сосын ұяшық индексін табамыз: i = hash(key) % m. Жақсы hash function кілттерді ұяшықтарға біркелкі таратады. Python-да hash("Алматы") жолдар үшін әр іске қосқанда өзгеруі мүмкін, ал бүтін сандар үшін hash(42) == 42.

Collision: соқтығысу

Екі түрлі кілт бір ұяшыққа түсуі мүмкін: бұл collision. Оны шешудің екі негізгі тәсілі бар.

  • Chaining: әр ұяшықта тізім. Соқтығысқан кілттер сол тізімге қосылады. Іздеу: ұяшықты табамыз да, тізімді аралаймыз.
  • Open addressing (linear probing): бәрі бір массивте. Ұяшық бос емес болса, келесі (i + 1) % m ұяшыққа қараймыз. Python-ның өз dict-і open addressing қолданады (күрделірек probing тізбегімен).
m = 8
buckets = [[] for _ in range(m)]
for key, val in [(10, "Нан"), (18, "Сүт"), (3, "Шай")]:
    buckets[hash(key) % m].append((key, val))
# 10 % 8 = 2 және 18 % 8 = 2: collision, екеуі де buckets[2] ішінде
print(buckets[2])   # [(10, 'Нан'), (18, 'Сүт')]

Load factor және rehashing

Load factor α = n / m, мұндағы n: элементтер саны. α өскен сайын тізбектер ұзарады, операция баяулайды. Сондықтан α белгілі шектен (мысалы, 0.75) асқанда, кесте rehashing жасайды: ұяшық санын екі есе көбейтіп, барлық кілтті жаңа % m бойынша қайта таратады. Бір rehash O(n), бірақ ол сирек болғандықтан, бір put-тің орташа (amortized) құны O(1) болып қалады.

ChainingLinear probing
Ұяшықтажұптар тізімібір жұп немесе бос
α > 1 бола маиәжоқ, α < 1 болуы шарт
Өшірутізімнен алып тастау«tombstone» белгісі керек
Кэшке ыңғайлыаздауиә, деректер қатар тұрады

Жиі қателер

  • put кезінде бар кілтті тексермей, екінші жұп қосу: кілт екі рет сақталады.
  • Rehash кезінде ескі индексті сақтау: жаңа m бойынша қайта есептеу міндетті.
  • Өзгермелі объектіні (list) кілт ету: оның hash-і жоқ.
  • Ең нашар жағдайды ұмыту: барлық кілт бір ұяшыққа түссе, операция O(n).
Кеңес: сұхбатта «dict неге O(1)?» деп сұраса, үш сөзді айтыңыз: hash function, collision шешу тәсілі және load factor-мен rehashing. «Орташа O(1), ең нашар O(n)» деп нақтылауды ұмытпаңыз.

4. Сызықтық сұрыптаулар және heapsort

DSA1-де insertion, merge және quick sort-ты көрдік. Салыстыруға негізделген кез келген сұрыптау ең нашар жағдайда кемінде O(n log n) салыстыру жасайды. Бірақ мәндер шағын аралықтағы бүтін сан болса, салыстырмай-ақ сызықтық уақытта сұрыптауға болады.

Counting sort

Емтихан баллдары 0-ден 100-ге дейін. Әр балл неше рет кездескенін санаймыз, сосын баллдарды ретімен шығарамыз. Уақыт O(n + k), мұндағы k: мәндер аралығының өлшемі. k кішкентай болса (100), бұл sorted-тан да жылдам; k өте үлкен болса (10⁹), жадқа сыймайды.

def counting_sort(a, max_value):
    count = [0] * (max_value + 1)
    for x in a:
        count[x] += 1
    out = []
    for v, c in enumerate(count):
        out.extend([v] * c)
    return out

Тұрақтылық (stability)

Сұрыптау тұрақты болса, кілті бірдей элементтер бастапқы ретін сақтайды. Студенттерді баллы бойынша сұрыптағанда, бірдей балл алғандар тізімде қалай тұрса, солай қалуы керек. Counting sort-ты тұрақты ету үшін әр баллға «себет» тізімін жасап, студенттерді кезекпен салып, себеттерді ретімен біріктіреміз. Python-ның sorted-ы да тұрақты, сондықтан бірнеше кілт бойынша кезекпен сұрыптауға болады.

Heapsort

DSA1-де heapq-ты дайын күйінде қолдандық. Енді heap-ті өзіміз басқарамыз. Массивтегі max-heap: i түйіннің балалары 2i + 1 және 2i + 2, ата-ананың мәні балаларынан кіші емес. Негізгі амал sift_down(a, i, n): i орнындағы мәнді үлкен баласымен ауыстыра отырып, төмен түсіреміз (тек [0, n) бөлігі heap деп есептеледі).

def sift_down(a, i, n):
    while True:
        big = i
        l, r = 2 * i + 1, 2 * i + 2
        if l < n and a[l] > a[big]: big = l
        if r < n and a[r] > a[big]: big = r
        if big == i:
            return
        a[i], a[big] = a[big], a[i]
        i = big

Heapsort екі кезеңнен тұрады: (1) n // 2 - 1-ден 0-ге дейін кері ретпен sift_down шақырып, heap құрамыз (O(n)); (2) ең үлкен a[0]-ді соңғы орынға ауыстырып, heap өлшемін бірге кемітеміз де, түбірге sift_down жасаймыз. Нәтиже: O(n log n) уақыт, O(1) қосымша жад, бірақ тұрақты емес.

АлгоритмОрташаЕң нашарЖадТұрақты
InsertionO(n²)O(n²)O(1)иә
MergeO(n log n)O(n log n)O(n)иә
QuickO(n log n)O(n²)O(log n)жоқ
HeapsortO(n log n)O(n log n)O(1)жоқ
CountingO(n + k)O(n + k)O(n + k)иә (себетпен)

Жиі қателер

  • sift_down-да heap шекарасын len(a) деп алу: сұрыпталған соңғы бөлік қайта бұзылады.
  • Heap құруды 0-ден бастау: төменнен жоғары, кері ретпен жүру керек.
  • Counting sort-ты теріс сандарға немесе үлкен аралыққа қолдану.
Кеңес: Python-да күнделікті жұмыста sorted жеткілікті (ол Timsort: тұрақты, O(n log n)). Heapsort пен counting sort-ты білу сұхбатта және шектеулер ерекше болғанда керек: жад O(1) болуы шарт немесе мәндер шағын бүтін сандар.

5. Теңгерімді ағаштар: AVL және айналдыру

DSA1-де BST-де іздеу, қосу O(h) екенін көрдік, мұндағы h: ағаштың биіктігі. Ағаш «толық» болса, h ≈ log₂ n. Бірақ мәселе бар: кілттер сұрыпталған ретпен келсе (мысалы, чек нөмірлері 1, 2, 3, ...), әр жаңа түйін оң жаққа қосылып, ағаш тізімге айналады. Сонда h = n, ал іздеу O(n).

Биіктік және balance factor

Бос ағаштың биіктігі 0, жалғыз түйіннің биіктігі 1 деп келісейік. Түйіннің balance factor-ы: height(left) - height(right). AVL ағашы: әр түйінде balance factor -1, 0 немесе 1. Мұндай ағаштың биіктігі шамамен 1.44·log₂ n-нан аспайды, сондықтан іздеу, қосу, өшіру әрқашан O(log n).

class Node:
    def __init__(self, key, left=None, right=None):
        self.key, self.left, self.right = key, left, right

def height(node):
    if node is None:
        return 0
    return 1 + max(height(node.left), height(node.right))

Айналдыру (rotation)

Жаңа кілт қосқаннан кейін бір түйіннің balance factor-ы 2 немесе -2 болса, оны айналдыру арқылы түзетеміз. Айналдыру BST ретін бұзбайды (inorder өзгермейді), тек O(1) сілтемені ауыстырады.

#        y                x
#       /               / #      x   C    →       A   y
#     /                   / #    A   B                B   C
def rotate_right(y):
    x = y.left
    y.left = x.right    # B енді y-тың сол баласы
    x.right = y
    return x            # жаңа түбір

Төрт жағдай бар:

  • LL (сол жақтың сол жағы ауыр): бір rotate_right.
  • RR: бір rotate_left.
  • LR: алдымен сол балаға rotate_left, сосын түйінге rotate_right.
  • RL: керісінше.

Мысал: 30, 10, 20 ретімен қосылса, 30-дың сол жағында 10, оның оң жағында 20 тұрады (LR). 10-ды солға айналдырып, сосын 30-ды оңға айналдырсақ, түбір 20, балалары 10 және 30.

Red-black tree

Тағы бір танымал теңгерімді ағаш: red-black tree. Әр түйін қызыл немесе қара, ал түстер ережесі ең ұзын жолдың ең қысқадан екі еседен аспауын қамтамасыз етеді. AVL қатаңырақ теңгерілген (іздеу сәл жылдам), red-black азырақ айналдыру жасайды (қосу/өшіру сәл жылдам). Java-ның TreeMap-і, C++-тың std::map-і red-black tree қолданады. Python стандартты кітапханасында теңгерімді ағаш жоқ: сұрыпталған тізім + bisect немесе heapq жиі жеткілікті.

Жиі қателер

  • Айналдырудан кейін жаңа түбірді ата-анаға қайтармау: ағаштың бір бөлігі «жоғалады».
  • y.left = x.right жолын ұмыту: B ішкі ағашы жоғалады.
  • is_balanced-та тек түбірді тексеру: теңгерім әр түйінде керек.
Кеңес: is_balanced-ты O(n)-де жазуға болады: көмекші функция ішкі ағаш теңгерімді болса биіктігін, болмаса -1 қайтарсын. Сонда биіктік әр түйінде бір рет қана есептеледі.

6. Union-Find және байланысқан компоненттер

DSA1-де компоненттерді BFS/DFS арқылы санадық: граф толық белгілі болса, бұл жақсы. Ал байланыстар бірінен соң бірі келсе ше? Мысалы, Қарағанды облысында жаңа жолдар салынып жатыр, әр жаңа жолдан кейін «Теміртау мен Балқаш байланысты ма?» деп сұраймыз. Әр жолы BFS жасау қымбат. Бұған Disjoint Set Union (DSU, union-find) құрылымы арналған.

Идея

Әр жиынның бір «өкілі» (түбірі) бар. parent[x]: x-тің ата-анасы, түбірдің ата-анасы өзі. Екі амал:

  • find(x): x-тің түбірін табу.
  • union(a, b): екі жиынды біріктіру, яғни бір түбірді екіншісіне ілу.

Екі элемент бір компонентте болуы үшін find(a) == find(b) жеткілікті.

Екі оңтайландыру

  • Path compression: find кезінде жолдағы барлық түйінді тікелей түбірге іледі. Келесі жолы олар бір қадамда табылады.
  • Union by rank: аласа ағашты биік ағашқа іледі, керісінше емес. rank: ағаш биіктігінің жоғарғы бағасы.

Екеуі бірге болса, бір амалдың орташа құны O(α(n)), мұндағы α: кері Аккерман функциясы, іс жүзінде 5-тен аспайды. Яғни дерлік O(1).

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
        self.count = n                  # компоненттер саны

    def find(self, x):
        root = x
        while self.parent[root] != root:
            root = self.parent[root]
        while self.parent[x] != root:   # path compression
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                # бұрыннан бір жиында
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        self.count -= 1
        return True

find итеративті жазылған: рекурсивті нұсқа ұзын тізбекте Python-ның рекурсия шегіне соғылуы мүмкін.

Цикл табу

Бағытсыз графтың қырларын бірінен соң бірі қосамыз. union(u, v) False қайтарса, u мен v бұрыннан байланысқан, демек жаңа қыр цикл жасайды. Бұл келесі сабақтағы Kruskal алгоритмінің негізі.

Жиі қателер

  • parent[a] = b деп түбірлерді емес, элементтердің өзін біріктіру: жиындар дұрыс біріктірілмейді.
  • Бір жиындағы екі элементті біріктіргенде count-ты азайту.
  • Атаулармен (жол түріндегі кілттер) жұмыс істегенде алдымен оларды индекске айналдыруды ұмыту: idx = {name: i for i, name in enumerate(names)}.
Кеңес: «топтарды біріктіру», «бір желіде ме», «қосылғанда цикл пайда бола ма» деген сұрақтар DSU-ды білдіреді. Ал «ең қысқа жол» немесе «қай ретпен» керек болса, BFS/DFS қажет: DSU жолды білмейді.

7. Dijkstra: салмақты графтағы ең қысқа жол

DSA1-де BFS барлық қыр бірдей болғанда ең қысқа жолды табады, ал Dijkstra-ның негізгі кодын бір есепте көрдік. Енді алгоритмді толық түсінеміз: неге дұрыс жұмыс істейді, жолды қалай қалпына келтіреміз және қашан жарамайды.

Салмақты граф

Қалалар арасындағы автобус жолдары: graph["Алматы"] = [("Қонаев", 70), ("Талдықорған", 270)]. Әр қырдың салмағы (км, минут, теңге) теріс емес. Мақсат: бастапқы қаладан басқа қалалардың әрқайсысына дейінгі ең аз қашықтық.

Алгоритм

Heap-те (қашықтық, төбе) жұптары. Әр қадамда heap-тен ең жақын төбені аламыз. Барлық салмақ теріс емес болғандықтан, оған бұдан қысқа жол табылмайды: оның қашықтығы «бекітілді». Сосын оның көршілерін relax етеміз: жаңа жол қысқа болса, жаңартып, heap-ке саламыз. Бір төбе heap-те бірнеше рет болуы мүмкін; ескірген жазбаны (d > dist[u]) өткізіп жібереміз.

import heapq

def dijkstra(graph, src):
    dist = {src: 0}
    prev = {}
    h = [(0, src)]
    while h:
        d, u = heapq.heappop(h)
        if d > dist[u]:
            continue
        for v, w in graph.get(u, []):
            nd = d + w
            if v not in dist or nd < dist[v]:
                dist[v] = nd
                prev[v] = u            # v-ға u арқылы келдік
                heapq.heappush(h, (nd, v))
    return dist, prev

Күрделілігі O((V + E) log V). Тек dict қолданғандықтан, төбелер кез келген hashable мән бола алады: қала атауы, тордағы (r, c) кортежі.

Жолды қалпына келтіру

prev[v] әр төбеге қайдан келгенімізді сақтайды. Мақсаттан бастап prev бойынша артқа жүріп, тізімді аударамыз:

path = [dst]
while path[-1] != src:
    path.append(prev[path[-1]])
path.reverse()     # ['Алматы', 'Қонаев', ...]

Теріс салмақ неге бұзады

Dijkstra «heap-тен алынған төбенің қашықтығы енді өзгермейді» деп сенеді. Теріс қыр болса, бұл дұрыс емес: A → C = 2 бекітілгеннен кейін A → B → C = 5 + (−4) = 1 табылуы мүмкін. Мұндай графқа Bellman-Ford алгоритмі керек: барлық қырды V − 1 рет relax етеді, O(V·E). Тағы бір рет relax мүмкін болса, графта теріс цикл бар: ол арқылы қашықтықты шексіз азайтуға болады.

Жиі қателер

  • Heap-ке (төбе, қашықтық) ретімен салу: heap төбе атауы бойынша сұрыптайды.
  • Ескірген жазбаларды өткізбеу: дұрыс, бірақ баяу.
  • Тек кілт ретінде бар төбелерді ескеру: кейбір төбе тек көрші ретінде кездеседі, graph.get(u, []) қолданыңыз.
  • Жеткізу мүмкін емес төбені тексермеу: prev-те жоқ болса, жол жоқ.
Кеңес: тек бір мақсатқа жол керек болса, heap-тен сол мақсат алынғанда бірден тоқтауға болады. Ірі карталарда бұл жұмысты бірнеше есе қысқартады.

8. Minimum spanning tree: Kruskal және Prim

Облыс әкімдігі бес ауылды асфальт жолмен қосқысы келеді. Кез келген екі ауыл арасында жол салудың бағасы белгілі. Барлық ауыл бір желіде болуы керек (тікелей не басқа ауыл арқылы), ал жалпы баға ең аз болуы керек. Бұл: minimum spanning tree (MST, ең аз қамтушы ағаш) есебі.

Анықтама

n төбелі байланысқан бағытсыз графтың spanning tree-і: барлық төбені қамтитын, циклсіз, n − 1 қырдан тұратын ішкі граф. MST: қыр салмақтарының қосындысы ең аз spanning tree. Ең қысқа жолмен шатастырмаңыз: MST екі нақты қала арасындағы ең қысқа жолды бермейді, ол бүкіл желінің жалпы құнын азайтады.

Kruskal

Идея өте қарапайым: қырларды салмағы бойынша сұрыптаймыз да, ең арзанынан бастап аламыз. Қыр цикл жасаса (екі шеті бұрыннан байланысқан), өткізіп жібереміз. Цикл тексеру: алдыңғы сабақтағы DSU.

def kruskal(n, roads):
    parent = list(range(n))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    total, used = 0, 0
    for u, v, cost in sorted(roads, key=lambda e: e[2]):
        ru, rv = find(u), find(v)
        if ru != rv:
            parent[ru] = rv
            total += cost
            used += 1
    return total if used == n - 1 else None   # None: граф байланыспаған

roads = [(0, 1, 4), (0, 2, 1), (1, 2, 2), (1, 3, 5), (2, 3, 8), (3, 4, 3)]
print(kruskal(5, roads))   # 1 + 2 + 3 + 5 = 11

Күрделілігі: сұрыптау O(E log E), DSU амалдары дерлік O(E).

Prim

Prim бір төбеден бастап ағашты «өсіреді». Heap-те ағаштан шығатын қырлар тұрады. Әр қадамда ең арзан қырды аламыз; оның екінші шеті ағашта жоқ болса, оны қосып, оның қырларын heap-ке саламыз. Бұл Dijkstra-ға ұқсас, бірақ heap-ке d + w емес, тек w салынады. Тығыз графта (қыр көп) Prim, сирек графта Kruskal ыңғайлы.

Неге greedy дұрыс жұмыс істейді

Cut property: төбелерді кез келген екі топқа бөлсек, топтарды қосатын ең арзан қыр қандай да бір MST-ге міндетті түрде кіреді. Kruskal да, Prim да әр қадамда дәл осындай қырды таңдайды. Бұл келесі сабақтағы greedy алгоритмдердің дәлелдеу тәсіліне жақсы мысал.

Жиі қателер

  • Граф байланыспаған жағдайды тексермеу: n − 1 қыр жиналмаса, MST жоқ.
  • Prim-де heap-тен алынған төбе ағашта бар-жоғын тексермеу: оның құны екі рет қосылады.
  • MST-ні ең қысқа жол деп ойлау.
Кеңес: егер кейбір жолдар бұрыннан салынған болса, оларды алдымен DSU-ға біріктіріп (құны 0), сосын Kruskal-ды қалған жолдармен жалғастырыңыз. Бұл нақты инфрақұрылым есептерінде жиі кездеседі.

9. Greedy алгоритмдер

Greedy (ашкөз) алгоритм әр қадамда «қазір ең жақсы көрінетін» таңдауды жасайды және оған қайта оралмайды. Kruskal мен Dijkstra greedy алгоритмдер еді. Greedy тез әрі қарапайым, бірақ қауіпті: көп есепте ол қате жауап береді. Сондықтан негізгі сұрақ: неге бұл жерде greedy дұрыс?

Interval scheduling

Шымкенттегі коворкингте бір мәжіліс залы бар. Командалар [start, end) уақытына брондау сұрайды. Ең көп кездесуді қалай орналастырамыз? Бірнеше «интуитивті» ереже бар: ең ерте басталатынын алу, ең қысқасын алу. Екеуі де қате. Дұрыс ереже: ең ерте аяқталатынын алу.

def max_meetings(intervals):
    count, free_at = 0, float("-inf")
    for s, e in sorted(intervals, key=lambda x: x[1]):
        if s >= free_at:         # [s, e) зал босағаннан кейін басталады
            count += 1
            free_at = e
    return count

print(max_meetings([(9, 12), (10, 11), (11, 13), (12, 14)]))   # 2

Жартылай ашық аралық болғандықтан, 11:00-де аяқталған кездесуден кейін 11:00-де жаңасы басталуы мүмкін: s >= free_at.

Exchange argument: бейресми дәлел

Кез келген оңтайлы кесте алайық. Оның бірінші кездесуін біздің таңдауымызбен (ең ерте аяқталатын) алмастырайық. Біздікі ертерек не сол уақытта аяқталады, сондықтан қалған кездесулерге кедергі жасамайды: кесте әлі де жарамды, кездесу саны өзгерген жоқ. Осылай қадам сайын алмастыра берсек, оңтайлы кесте біздің greedy кестемізге айналады. Демек greedy оңтайлы. Бұл тәсіл exchange argument деп аталады: «оңтайлы шешімді greedy таңдауға жақындатқанда, ол нашарламайды».

Тиын беру: greedy қашан жұмыс істейді

Кассир 1, 2, 5, 10, 20, 50, 100, 200 теңгелік монеталармен қайтарым береді. Greedy: ең үлкен монетаны мүмкін болғанша алу. Мұндай «канондық» жүйелерде greedy монета санын азайтады. Бірақ жүйе басқаша болса:

coins = [1, 3, 4], amount = 6
greedy:  4 + 1 + 1   → 3 монета
оңтайлы: 3 + 3       → 2 монета

Мұнда greedy қате. Оңтайлы жауап үшін DSA1-дегі coin change DP керек. Монеталар жүйесін тексеру үшін greedy мен DP нәтижесін көп сомада салыстыруға болады: бұл келесі тапсырмалардың бірі.

Greedy-ді қалай тану керек

  • Таңдау «жергілікті» және кейін ешқандай таңдауға кедергі жасамайды.
  • Сұрыптаудан кейін бір өту жеткілікті (интервалдар, тапсырмалар, бағалар).
  • Exchange argument құрастыруға болады.
  • Кішкентай қарсы мысал таппасаңыз (brute force-пен салыстырып), greedy-ге сенімділік артады.

Жиі қателер

  • Интервалдарды басталу уақыты бойынша сұрыптау.
  • Greedy-ді дәлелсіз қолдану: 0/1 knapsack-те «бағасы/салмағы ең жоғарысын алу» қате (бөлшек knapsack-те дұрыс).
  • Шекарадағы теңдікті ұмыту: > мен >= айырмасы.
Кеңес: greedy идеясын тапқанда, оны бірден brute force-пен кездейсоқ шағын кірістерде салыстырыңыз. Қарсы мысал табылса, есеп DP-ге жақын болуы ықтимал.

10. DP II: LIS, knapsack, edit distance, bitmask

DSA1-де DP-нің негізін көрдік: күй, ауысу, базалық жағдай; LIS ұзындығын O(n log n)-де және edit distance-ты 2D кестемен есептедік. Енді бір қадам әрі: жауаптың өзін қалпына келтіру, ресурсқа шектеулі таңдау және ішкі жиындар бойынша DP.

LIS-ті қалпына келтіру

tails[k]: ұзындығы k + 1 өспелі тізбектің ең кіші соңғы мәні. Тізбектің өзін алу үшін tails_idx[k] (сол мәннің индексі) және prev[i] (i-ден алдыңғы элементтің индексі) сақтаймыз. Соңында ең ұзын тізбектің соңынан prev бойынша артқа жүреміз. Бұл Dijkstra-дағы prev-пен бірдей идея.

0/1 knapsack

Студент Бурабайға жорыққа шығады, рюкзак ең көбі W кг көтереді. Әр заттың салмағы мен пайдасы бар, әр затты бір рет алуға болады. dp[w]: салмағы w-дан аспайтын ең жоғары пайда.

def knapsack(items, W):
    dp = [0] * (W + 1)
    for weight, value in items:
        for w in range(W, weight - 1, -1):   # КЕРІ ретпен!
            dp[w] = max(dp[w], dp[w - weight] + value)
    return dp[W]

print(knapsack([(3, 40), (4, 50), (2, 30)], 6))   # 80: 4 кг + 2 кг

Ішкі цикл неге кері? Алға жүрсек, dp[w - weight] осы заттың өзін қамтып үлгеруі мүмкін: бір затты екі рет аламыз (бұл шексіз knapsack болып кетеді). Уақыт O(n·W), жад O(W).

Edit distance-ты қолдану

DSA1-дегі edit_distance(a, b) бір символды қою, өшіру немесе ауыстыру санын береді. Нақты қолдану: іздеу жолағындағы қате теруді түзету. Қолданушы «Алмты» деп терсе, қалалар тізімінен қашықтығы ең аз сөзді ұсынамыз. Ұзын жолдарда кестенің тек екі қатарын сақтасақ, жад O(min(n, m)) болады.

Bitmask DP

Курьер қоймадан (0) шығып, n нүктенің бәріне барып, қоймаға оралады. Барлық ретті тексеру O(n!). Ішкі жиын бойынша DP: dp[mask][v] = mask-тағы нүктелерге барып, v-да тұрған кездегі ең қысқа жол. mask: биттері барылған нүктелерді білдіретін бүтін сан.

mask = 0b1011        # 0, 1, 3 нүктелеріне бардық
mask >> 2 & 1       # 0: 2-нүктеге әлі бармадық
mask | (1 << 2)      # 0b1111: 2-нүктені қостық

Күйлер саны 2ⁿ · n, әр күйден n ауысу: O(2ⁿ · n²). n = 15 үшін бұл шамамен 7 млн, ал 15! ≈ 1.3 трлн.

Жиі қателер

  • 0/1 knapsack-те ішкі циклді алға жүргізу.
  • LIS-те қатаң өсу үшін bisect_left, қатаң емес үшін bisect_right керегін шатастыру.
  • Bitmask-та операция басымдығы: mask & 1 << v емес, mask & (1 << v) деп жақшамен жазыңыз.
Кеңес: n ≤ 20 шектеуін көрсеңіз, bitmask DP-ді ойлаңыз. W ≤ 10⁴ сияқты шағын «сыйымдылық» болса, knapsack тәрізді 1D DP-ді ойлаңыз.

11. Жолдар алгоритмдері: prefix function және KMP

DSA1-де жолдармен жұмыс істеп, палиндром мен анаграммаларды тексердік. Енді классикалық есеп: ұзын мәтіннен (text, ұзындығы n) үлгіні (pattern, ұзындығы m) табу. Аңғал тәсіл әр позицияда үлгіні басынан салыстырады: ең нашар жағдайда O(n·m). Мысалы, мәтін "aaaa...a", үлгі "aaa...ab" болса, әр позицияда m − 1 символ сәйкес келіп, соңында сәтсіз болады.

Prefix function

pi[i]: s[0..i] префиксінің ең ұзын меншікті (өзіне тең емес) префиксінің ұзындығы, ол сол префикстің суффиксі де болады. Мысалы, s = "abcabd":

i012345
s[i]abcabd
pi[i]000120

i = 4-те "abcab" префиксі "ab"-мен басталып, "ab"-мен аяқталады: pi = 2.

def prefix_function(s):
    pi = [0] * len(s)
    for i in range(1, len(s)):
        k = pi[i - 1]
        while k > 0 and s[i] != s[k]:
            k = pi[k - 1]            # қысқарақ «шекараға» секіреміз
        if s[i] == s[k]:
            k += 1
        pi[i] = k
    return pi

Неге O(n)? k әр қадамда ең көбі 1-ге өседі, ал while оны тек азайтады. Барлық азайту саны барлық өсуден аспайды.

KMP іздеу

Knuth-Morris-Pratt алгоритмі: сәйкессіздік болғанда мәтінде артқа оралмаймыз, үлгіде pi бойынша секіреміз. Ең оңай жазу тәсілі: pattern + "#" + text жолының prefix function-ын есептеу. "#" екі жолда да жоқ символ болуы керек. pi[i] == m болған жерде үлгі аяқталды, оның мәтіндегі басы i - 2m. Уақыт O(n + m).

Нақты мысал: оқушылардың эсселерінен «жасанды интеллект» тіркесінің неше рет кездесетінін санау, логтардан қате кодын табу, ДНҚ тізбегінен үлгі іздеу.

String hashing

Тағы бір тәсіл: жолды санға айналдыру. Полиномдық hash: h(s) = (s[0]·Bᵐ⁻¹ + s[1]·Bᵐ⁻² + ... + s[m−1]) mod M. Терезе бір символға жылжығанда hash-ті O(1)-де жаңартуға болады (rolling hash, Rabin-Karp алгоритмі). Екі жолдың hash-і тең болмаса, жолдар әртүрлі; тең болса, ықтимал тең, себебі collision болуы мүмкін. Сондықтан hash сәйкес келгенде жолдарды тікелей салыстырып тексереміз немесе екі түрлі M қолданамыз.

Жиі қателер

  • Сәйкестік табылғаннан кейін іздеуді тоқтату: қабаттасқан кездесулер өткізіліп кетеді ("aa" үлгісі "aaa"-да 2 рет).
  • Python-ның str.count қабаттаспайтын кездесулерді санайды: "aaa".count("aa") == 1.
  • Бөлгіш символ мәтінде кездеседі: "#" орнына мәтінде жоқ символ таңдаңыз немесе бөлек KMP циклін жазыңыз.
  • Бос үлгіні ескермеу.
Кеңес: prefix function тек іздеу үшін емес. Ол жолдың ең қысқа периодын да береді: p = n - pi[n - 1], ал n % p == 0 болса, жол p ұзындықты бөліктің қайталануы.

12. Trie: префикс ағашы және автотолықтыру

Kaspi-стильді дүкен қосымшасының іздеу жолағына «сүт» деп тергенде «сүт», «сүтті шоколад», «сүзбе» емес, «сүт...»-тен басталатын тауарлар ұсынылуы керек. Сөздер тізімін әр жолы толық аралау O(N·L). Бұған арнайы құрылым бар: trie (префикс ағашы).

Құрылымы

Trie-дің әр түйіні бір символды білдіреді, түбірден түйінге дейінгі жол: бір префикс. Әр түйінде балалары (символ → түйін сөздігі) және «осы жерде сөз аяқтала ма» деген белгі бар. Ортақ префиксі бар сөздер ортақ түйіндерді бөліседі.

class TrieNode:
    def __init__(self):
        self.children = {}
        self.end = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            node = node.children.setdefault(ch, TrieNode())
        node.end = True

    def _walk(self, s):
        node = self.root
        for ch in s:
            node = node.children.get(ch)
            if node is None:
                return None
        return node

    def search(self, word):
        node = self._walk(word)
        return node is not None and node.end

    def starts_with(self, prefix):
        return self._walk(prefix) is not None

Барлық амал O(L), мұндағы L: сөз немесе префикс ұзындығы. Сөздер саны N-ге тәуелді емес.

Автотолықтыру

Префикс түйініне жеткен соң, одан төмен DFS жасап, end белгісі бар түйіндердің сөздерін жинаймыз. Балаларды sorted(node.children) ретімен аралағанда, сөздер алфавит бойынша шығады, сондықтан алғашқы k сөзден кейін тоқтай аламыз.

Санауыштар

«Осы префикспен неше сөз басталады?» сұрағын жиі қоямыз. Әр түйінге count өрісін қосамыз: insert кезінде жолдағы әр түйіннің count-ын 1-ге арттырамыз. Сонда жауап префикс түйінінің count-ы, O(L).

Жадазазкөп (әр түйін dict)

Python-да шағын тапсырмалар үшін сұрыпталған тізім мен bisect жиі жеткілікті. Trie префикс сұраулары өте көп болғанда, сөздер ағыны үздіксіз келгенде немесе әр префикске қосымша ақпарат (санауыш, ең танымал сөз) сақтау керек болғанда ұтады.

Жиі қателер

  • search-те end белгісін тексермеу: «сүт» сөзі болса, «сү» де табылып кетеді.
  • Бос жолды ескермеу: starts_with("") әрқашан True.
  • Бір сөзді екі рет қосқанда санауышты қайта арттыру (егер есеп қайталанбайтын сөздерді санаса).
Кеңес: түйінді бөлек класс емес, жай сөздік ретінде де жазуға болады: node = node.setdefault(ch, {}), ал сөз соңын "$" кілтімен белгілейміз. Код қысқарады, бірақ символдар ішінде "$" болмауы керек.

13. Модуль емтиханы: Advanced Algorithms

Емтихан бүкіл модульді қамтиды: sliding window, union-find мен MST, Dijkstra, KMP және алгоритм таңдау. Өту үшін ұпайдың кемінде 75%-ын жинау керек.

  • Функция атаулары мен қайтарылатын мән түрі дәл берілгендей болуы керек.
  • Әр тапсырмада тесттер шеткі жағдайларды да (бос кіріс, жету мүмкін емес төбе, бір элемент) және жылдамдықты да тексереді.
  • Алдымен brute force-ты ойлаңыз, сосын қай құрылым оны жылдамдататынын таңдаңыз. Кеңестер берілмейді.
