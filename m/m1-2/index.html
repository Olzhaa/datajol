M1.2 SQL Core: SQL негіздері қазақша

Бұл модульде онлайн дүкеннің дерекқорымен жұмыс істейсіз: клиенттер, тауарлар, тапсырыстар. Сұрауды оң жақтағы редакторға жазып, «Іске қосу» батырмасымен нәтижені көріңіз, сосын «Тексеру» батырмасын басыңыз.

Тіркелмей бірінші сабақты бастау Барлық тапсырмалар

1. Дерекқор және бірінші SELECT

SQL (Structured Query Language) — дерекқордағы кестелерге сұрақ қоятын тіл. Банк, дүкен, такси қосымшасы — барлығының ішінде SQL дерекқоры бар.

Біздің дүкен дерекқорында төрт кесте бар:

КестеБағандар
customersid, name, city, signup_date
productsid, name, category, price
ordersid, customer_id, order_date, status
order_itemsorder_id, product_id, quantity

SELECT ... FROM

Ең қарапайым сұрау кестедегі бәрін алады. * белгісі «барлық бағандар» дегенді білдіреді:

SELECT * FROM customers;

Тек керекті бағандарды үтірмен бөліп атауға болады:

SELECT name, city FROM customers;
SQL кілт сөздерін (SELECT, FROM) бас әріппен жазу — дәстүр ғана. select да жұмыс істейді. Сұрау соңындағы ; сұрауларды бір-бірінен бөледі.

Сұрау қалай орындалады?

Сіз сұрауды жазасыз, дерекқор оны оқып, кестеден жолдарды алып, нәтижені жаңа кесте түрінде қайтарады. Бастапқы кесте өзгермейді: SELECT тек оқиды, сондықтан қорықпай тәжірибе жасай беріңіз.

Неге *-ны абайлап қолданамыз?

  • Нақты жұмыста кестеде ондаған, тіпті жүздеген баған болады. SELECT * артық деректі алып, сұрауды баяулатады.
  • Кейін кестеге жаңа баған қосылса, * нәтижесі өзгеріп кетеді де, есеп бұзылуы мүмкін.
  • Бағандарды атап жазсаңыз, сұрауды оқыған адам не алынып жатқанын бірден түсінеді.

Сондықтан *-ны кестемен алғаш танысқанда қолданыңыз, ал тұрақты сұрауларда бағандарды атаңыз.

Үлкен кестеге алғаш қарағанда соңына LIMIT 10 қосыңыз: дерекқор бүкіл кестені емес, тек 10 жолды қайтарады. Бұл туралы ORDER BY сабағында толығырақ айтамыз.

2. WHERE: жолдарды сүзу

WHERE шарты тек керекті жолдарды қалдырады. Ол FROM-нан кейін жазылады:

SELECT name, price
FROM products
WHERE price > 50000;

Салыстыру операторлары

ОператорМағынасы
=тең
<> немесе !=тең емес
>, <үлкен, кіші
>=, <=үлкен немесе тең, кіші немесе тең

Мәтін мен күн бір тырнақшаға алынады: WHERE city = 'Алматы'. Сандар тырнақшасыз: WHERE price = 9000.

Күндер '2024-09-01' форматында сақталған. Бұл форматты мәтін ретінде салыстыру да дұрыс жұмыс істейді: order_date >= '2024-10-01'.

WHERE қалай жұмыс істейді?

Дерекқор шартты кестенің әр жолы үшін тексереді. Шарт TRUE болса, жол нәтижеге кіреді, FALSE немесе белгісіз болса, кірмейді. Сондықтан WHERE ешқашан жаңа жол жасамайды, тек бар жолдарды сүзеді.

Жиі кездесетін қателер

  • Қос тырнақша: city = "Алматы". Стандартты SQL-де қос тырнақша баған атауын білдіреді, мәтін үшін бір тырнақша жазыңыз.
  • Регистр: 'алматы' мен 'Алматы' әртүрлі мәтін. Деректегі жазылуын алдымен SELECT DISTINCT city арқылы қараңыз.
  • Артық бос орын: соңында бос орны бар 'Алматы ' мәні шартқа сәйкес келмейді. Мұндай мәндерді дерек тазалау модулінде түзетеміз.
  • Санды мәтін ретінде салыстыру: price > '50000' кейбір дерекқорларда мәтін ретінде салыстырылып, күтпеген нәтиже береді. Санды тырнақшасыз жазыңыз.
Шартты тексерудің оңай жолы: алдымен WHERE-сіз сұрау жасап, бірнеше жолды көзбен қараңыз, сосын шартты қосып, жолдар саны күткендей азайғанын тексеріңіз.

3. AND, OR, NOT, BETWEEN, IN

Бірнеше шартты біріктіру үшін логикалық операторлар бар:

  • AND — екі шарт та орындалуы керек.
  • OR — кемінде бір шарт орындалса жеткілікті.
  • NOT — шартты керісінше өзгертеді.
SELECT name, price FROM products
WHERE category = 'Электроника' AND price < 100000;

BETWEEN және IN

BETWEEN a AND b — аралық, шеттерін қоса алғанда. IN (...) — тізімдегі мәндердің біріне тең.

WHERE price BETWEEN 5000 AND 20000
WHERE city IN ('Алматы', 'Шымкент')
WHERE city NOT IN ('Алматы')
AND пен OR араласса, жақша қойыңыз: WHERE (city = 'Алматы' OR city = 'Астана') AND status = 'delivered'. Жақшасыз AND бірінші орындалады.

Шарттардың басымдығы

SQL алдымен NOT, сосын AND, соңында OR операторын орындайды. Мына шарт:

WHERE city = 'Алматы' OR city = 'Астана' AND status = 'delivered'

шын мәнінде city = 'Алматы' OR (city = 'Астана' AND status = 'delivered') деп оқылады: Алматы бойынша кез келген статустағы жолдар шығады. Жақша қою қатені болдырмайды және сұрауды оқуды жеңілдетеді.

BETWEEN және күндер

BETWEEN екі шетін де қамтиды. Күн мен уақыт бірге сақталса ('2024-09-30 14:00'), BETWEEN '2024-09-01' AND '2024-09-30' 30 қыркүйектегі түстен кейінгі жазбаларды өткізіп жібереді, себебі ол мәтін ретінде '2024-09-30'-дан үлкен. Мұндай жағдайда келесі айдың басымен шектеу сенімдірек:

WHERE order_date >= '2024-09-01' AND order_date < '2024-10-01'
NOT IN тізімінде NULL болса, шарт ешбір жол үшін орындалмайды. Тізімді қолмен жазғанда NULL қоспаңыз, ал ішкі сұраудан алсаңыз, WHERE ... IS NOT NULL қосыңыз.

4. LIKE және NULL

LIKE: үлгі бойынша іздеу

% — кез келген таңбалар тізбегі, _ — дәл бір таңба.

WHERE name LIKE 'Кітап%'   -- «Кітап» сөзінен басталады
WHERE name LIKE '%фон'     -- «фон» сөзімен аяқталады
WHERE name LIKE '%ал%'     -- ішінде «ал» бар

NULL: мән жоқ

NULL — «белгісіз» немесе «бос». Ол нөл де, бос мәтін де емес. Сондықтан = NULL жұмыс істемейді, арнайы оператор керек:

WHERE city IS NULL
WHERE city IS NOT NULL
Нақты деректе NULL өте жиі кездеседі. Талдау алдында қай бағандарда бос мән бар екенін әрқашан тексеріңіз.

LIKE туралы қосымша

  • SQLite-та LIKE латын әріптері үшін регистрге сезімтал емес: 'a%' «Apple»-ді де табады. Бірақ кириллицада бұл ереже жұмыс істемейді, «кітап» пен «Кітап» әртүрлі.
  • Регистрге тәуелсіз іздеу үшін екі жағын да бірдей регистрге келтіріңіз: WHERE LOWER(name) LIKE '%phone%'.
  • Басында % тұрған үлгі ('%фон') индексті қолдана алмайды, сондықтан үлкен кестеде баяу жұмыс істейді.

NULL арифметикада және салыстыруда

NULL-мен кез келген амал NULL береді: 5 + NULL = NULL, NULL = NULL да TRUE емес, NULL. Сондықтан WHERE city <> 'Алматы' қаласы бос клиенттерді де көрсетпейді: олар үшін шарт белгісіз.

Бос мәнді басқа мәнмен алмастыру үшін COALESCE бар:

SELECT name, COALESCE(city, 'белгісіз') AS city FROM customers;
Бағандағы бос мәндерді санаудың тез тәсілі: SELECT COUNT(*) - COUNT(city) FROM customers. COUNT(city) NULL-ды санамайды, ал айырма бос мәндер санын береді.

5. ORDER BY, LIMIT, DISTINCT

ORDER BY нәтижені сұрыптайды. ASC — өсу ретімен (әдепкі), DESC — кему ретімен.

SELECT name, price FROM products
ORDER BY price DESC;

LIMIT n — тек алғашқы n жолды қалдырады. ORDER BY-мен бірге «топ-N» алу үшін қолданылады.

DISTINCT — қайталанатын жолдарды алып тастайды:

SELECT DISTINCT category FROM products;

Сұрау бөліктерінің реті

SELECT ... FROM ... WHERE ... ORDER BY ... LIMIT ...

Бірнеше баған бойынша сұрыптау

ORDER BY-ға бірнеше бағанды үтірмен беруге болады. Бірінші бағандағы мәндер тең болса, екінші баған бойынша сұрыпталады:

SELECT name, category, price FROM products
ORDER BY category ASC, price DESC;

Нәтижеде санаттар әліпби ретімен, ал әр санаттың ішінде тауарлар қымбаттан арзанға қарай тұрады.

Жиі кездесетін қателер

  • ORDER BY-сыз LIMIT: дерекқор жолдарды кез келген ретпен қайтара алады, сондықтан «алғашқы 5» әр орындалған сайын әртүрлі болуы мүмкін. Топ-N алғанда әрқашан ORDER BY жазыңыз.
  • Тең мәндер: 3-ші және 4-ші тауарлардың бағасы бірдей болса, LIMIT 3 біреуін кездейсоқ қалдырады. Тұрақты нәтиже үшін екінші сұрыптау бағанын (мысалы, id) қосыңыз.
  • NULL реті: SQLite-та NULL өсу ретімен сұрыптағанда басында, кему ретімен сұрыптағанда соңында тұрады. Басқа дерекқорларда керісінше болуы мүмкін.
DISTINCT бүкіл жолға қолданылады: SELECT DISTINCT city, signup_date қала мен күннің бірегей жұптарын береді, тек қалаларды емес.

6. Alias және есептелген бағандар

SELECT ішінде арифметика жасауға болады: + - * /. Жаңа бағанға AS арқылы атау (alias) береміз:

SELECT name,
       price,
       price * 1.12 AS price_with_vat
FROM products;

Кестеге де қысқа атау беруге болады. Бұл JOIN сабағында өте пайдалы болады:

SELECT p.name FROM products AS p;
SELECT p.name FROM products p;   -- AS міндетті емес
SQLite-та бүтін санды бүтін санға бөлсеңіз, нәтиже де бүтін болады: 7 / 2 = 3. Дәл нәтиже үшін біреуін бөлшек санға айналдырыңыз: 7 / 2.0 = 3.5.

Есептелген бағандардың мысалдары

SELECT name,
       price,
       ROUND(price * 0.85) AS after_discount,
       price - 5000       AS minus_coupon
FROM products;

ROUND(x) бүтінге, ROUND(x, 1) бір ондық таңбаға дейін дөңгелектейді. Мәтінді || арқылы біріктіруге болады: name || ' (' || category || ')'.

Alias-ты қай жерде қолдануға болады?

Сұрау бөліктері жазылу ретімен орындалмайды: дерекқор алдымен FROM мен WHERE-ді, сосын SELECT-ті, соңында ORDER BY-ды орындайды. Сондықтан alias-ты ORDER BY-да қолдануға болады, ал WHERE-де болмайды:

SELECT name, price * 1.12 AS price_with_vat
FROM products
ORDER BY price_with_vat DESC;   -- дұрыс

WHERE-де есептеуді қайта жазу керек: WHERE price * 1.12 > 50000.

Alias-қа бос орынсыз, латын әріптерімен атау беріңіз: price_with_vat. Бос орын болса, атауды қос тырнақшаға алу керек, ал кейінгі сұрауларда бұл ыңғайсыз.

7. Агрегат функциялар

Дүкен кассасын елестетіңіз. Кассир чектегі әр тауарды жеке айтпайды, соңында бір сан айтады: «Барлығы 41 700 ₸». Агрегат функциялар да солай жасайды: көп жолды алып, бір санға жинақтайды. Менеджердің «қанша клиент бар?», «орташа баға қандай?» деген сұрақтарының бәрі осылай шешіледі. Олар Excel-дегі COUNT, SUM, AVERAGE формулалары сияқты жұмыс істейді.

ФункцияНе қайтарады
COUNT(*)жолдар саны
COUNT(col)NULL емес мәндер саны
SUM(col)қосынды
AVG(col)орташа мән
MIN(col), MAX(col)ең кіші, ең үлкен

Мысал: бір сұрауда бірнеше функция

products кестесінде тек 4 тауар бар деп елестетейік:

idnamecategoryprice
2ҚұлаққапЭлектроника25000
4Кітап: SQL негіздеріКітаптар6500
7ТермосАксессуарлар9000
9БлокнотКеңсе1200
SELECT COUNT(*)   AS n,
       SUM(price) AS total,
       AVG(price) AS avg_price,
       MAX(price) AS max_price
FROM products;

Нәтиже — 4 жол емес, бір жол. Бағандар SELECT-те жазылған ретпен шығады:

ntotalavg_pricemax_price
4417001042525000

Есептеу: 25000 + 6500 + 9000 + 1200 = 41700, ал 41700 / 4 = 10425. Агрегатты WHERE-пен бірге қолдануға болады: алдымен жолдар сүзіледі, сосын қалғаны жинақталады:

SELECT COUNT(*) AS n, AVG(price) AS avg_price
FROM products
WHERE category = 'Электроника';

COUNT-тың үш түрі

Төрт клиент: Айгерім (Алматы), Ержан (Алматы), Бауыржан (қаласы NULL), Жанар (Ақтөбе).

ӨрнекНәтижеНеге
COUNT(*)4барлық жол
COUNT(city)3NULL саналмайды
COUNT(DISTINCT city)2Алматы, Ақтөбе

Жиі қателер

  • COUNT пен SUM-ды шатастыру. COUNT(quantity) — қанша жол бар, ал SUM(quantity) — барлық тауар данасының қосындысы. Бір жолда 5 блокнот болса, COUNT оны 1 деп, SUM 5 деп санайды.
  • Агрегат пен қарапайым бағанды араластыру: SELECT name, MAX(price). Мұндай сұрауда name қай жолдан алынатыны түсініксіз. Ең қымбат тауардың атауын білу үшін ORDER BY price DESC LIMIT 1 жазыңыз, ал «әр топ үшін» есептеуді келесі сабақта GROUP BY арқылы үйренеміз.
  • NULL-ды ұмыту. SUM, AVG, MIN, MAX NULL мәндерді елемейді. Сондықтан AVG бос мәндерді нөл деп санамайды.

8. GROUP BY және HAVING

Өткен сабақта агрегат бүкіл кестеге бір сан берді. Ал «әр қалада қанша клиент?» деген сұраққа бір сан жетпейді. Үстелдегі чектерді қала бойынша үйінділерге бөліп, әр үйіндіні бөлек санайтыныңызды елестетіңіз. GROUP BY дәл осылай жасайды: жолдарды топтарға бөліп, әр топқа агрегат есептейді. Бұл Excel-дегі pivot table сияқты.

Мысал: әр қаладағы клиенттер

idnamecity
1АйгерімАлматы
2НұрланАстана
4ЕржанАлматы
6ТимурАстана
7ӘсемАлматы
SELECT city, COUNT(*) AS customers
FROM customers
GROUP BY city;

SQL алдымен екі топ құрады: «Алматы» (Айгерім, Ержан, Әсем) және «Астана» (Нұрлан, Тимур). Сосын әр топтағы жолдарды санайды. Нәтижеде әр топқа бір жол:

citycustomers
Алматы3
Астана2

SELECT-ке бірнеше агрегатты қатар жазуға болады, мысалы COUNT(*) пен AVG(price) бірге — әр топ үшін екеуі де есептеледі.

Ереже: SELECT-тегі агрегат емес әр баған GROUP BY-да да болуы керек.

HAVING: топтарды сүзу

WHERE топтауға дейін жолдарды сүзеді. HAVING топтаудан кейін топтарды сүзеді. Сондықтан агрегат бойынша шарт (COUNT(*), AVG(price)) тек HAVING-те жазылады. Жоғарыдағы кестеден кемінде 3 клиенті бар қалаларды ғана қалдырайық:

SELECT city, COUNT(*) AS customers
FROM customers
GROUP BY city
HAVING COUNT(*) >= 3;
citycustomers
Алматы3

Астана тобында 2 жол бар, шарт орындалмады, сондықтан ол нәтижеге кірмеді. Тағы бір мысал — орташа бағасы 10 000-нан жоғары санаттар:

SELECT category, AVG(price) AS avg_price
FROM products
GROUP BY category
HAVING AVG(price) > 10000;

Толық реті: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT.

Жиі қателер

  • Агрегатты WHERE-ге жазу: WHERE COUNT(*) > 1 қате береді. WHERE орындалғанда топтар әлі жоқ — HAVING қолданыңыз.
  • GROUP BY-ды ұмыту. SELECT city, COUNT(*) FROM customers әр қалаға емес, бүкіл кестеге бір жол қайтарады.
  • NULL тобын байқамау. city бағаны бос жолдар бөлек NULL тобына жиналады. Ол керек болмаса, WHERE city IS NOT NULL қосыңыз.

9. CASE WHEN: шартты бағандар

Мұғалім жұмыстарды тексергенде әр ұпайға баға қояды: 85-тен жоғары болса «5», 70-тен жоғары болса «4», әйтпесе «3». CASE — SQL-дегі дәл осындай «егер ... онда ...». Ол әр жол үшін шартты тексеріп, жаңа баған жасайды. Excel-дегі IF формуласына ұқсайды, бірақ бірнеше шартты қатар жазу оңай.

CASE
  WHEN шарт1 THEN мән1
  WHEN шарт2 THEN мән2
  ELSE қалғандарына мән
END AS жаңа_баған

Шарттар жоғарыдан төмен тексеріледі, бірінші орындалғаны алынады да, қалғандары қаралмайды.

Мысал: бағаны деңгейге бөлу

  CASE
    WHEN price >= 20000 THEN 'жоғары'
    WHEN price >= 5000 THEN 'орта'
    ELSE 'төмен'
  END AS level
FROM products;

Термосты қарайық: 9000 ≥ 20000 емес, бірінші шарт өтпеді. 9000 ≥ 5000 — екінші шарт өтті, сондықтан «орта». Блокнотқа ешбір шарт келмеді, ол ELSE-ке түсті.

Шарт мәтінмен де жазылады: WHEN city = 'Алматы' THEN 'Алматы' ELSE 'өңірлер'. Мәтін әрқашан жалғыз тырнақшада болады.

CASE + GROUP BY

CASE-ке alias беріп, сол alias бойынша топтасаңыз, өз сегменттеріңіз бойынша санай аласыз:

SELECT

    WHEN price >= 20000 THEN 'жоғары'
    WHEN price >= 5000 THEN 'орта'
    ELSE 'төмен'
  END AS level,
  COUNT(*) AS n
FROM products
GROUP BY level;

SQL алдымен әр жолға деңгей береді (жоғарыдағы кесте), сосын бірдей деңгейдегі жолдарды бір топқа жинап, санайды. Шартта бір ғана мәнді тексеріп, қалғанының бәрін ELSE-пен бір топқа жинауға да болады — сонда нәтижеде екі топ қана болады. Alias бойынша GROUP BY SQLite пен PostgreSQL-де жұмыс істейді; кейбір дерекқорларда CASE өрнегін GROUP BY-ға толық қайта жазу керек.

Жиі қателер:
  • Шарттардың реті. WHEN price >= 5000 бірінші тұрса, Ноутбук та «орта» болып кетеді. Үлкен шекарадан бастаңыз.
  • ELSE-ті ұмыту. ELSE болмаса, ешбір шартқа келмеген жолдар NULL алады.
  • END-ті ұмыту немесе үтірді қате қою. CASE ... END — бір баған, одан кейін үтір қойылады.

10. JOIN: кестелерді біріктіру

Деректер бірнеше кестеге бөлінген: тапсырыста тек customer_id бар, ал клиенттің аты customers кестесінде. Курьерді елестетіңіз: оның қолында «3-клиентке жеткізу» деген қағаз бар, ал аты-жөнін білу үшін ол клиенттер дәптерінен 3 нөмірін іздейді. JOIN осы іздеуді әр жол үшін автоматты жасайды. Excel-дегі XLOOKUP-қа ұқсайды, бірақ бірден бүкіл кестеге.

ON — қай бағандар арқылы байланысатынын көрсетеді. Әдетте бұл foreign key (orders.customer_id) мен primary key (customers.id).

INNER JOIN

JOIN = INNER JOIN: екі кестеде де сәйкесі бар жолдар ғана қалады. Тапсырыс жасамаған клиент нәтижеге кірмейді — мысалдағы Дана жоқ.

JOIN-нан кейін әдеттегідей WHERE, ORDER BY, GROUP BY жаза бересіз. Мысалы, тек Айгерімнің тапсырыстары: ... JOIN ... ON ... WHERE c.name = 'Айгерім'.

Екі кестеде бірдей атаулы баған болса (мысалы id, name), кесте атауын немесе alias-ты міндетті түрде жазыңыз: c.name, p.name.

Табысты есептеу

Тапсырыс табысы = дана × баға. Дана саны order_items-та, баға products-та, сондықтан оларды біріктіреміз:

SELECT oi.order_id, SUM(oi.quantity * p.price) AS revenue
FROM order_items oi
JOIN products p ON p.id = oi.product_id
GROUP BY oi.order_id;

  • Ретті шатастыру. WHERE JOIN-нан бұрын емес, кейін жазылады: FROM → JOIN ... ON → WHERE → GROUP BY.

11. LEFT JOIN және бірнеше JOIN

Сынып журналын елестетіңіз: оқушылардың тізімі толық тұрады, ал сабаққа келмеген оқушының бағасы бос қалады. Оны тізімнен ешкім өшірмейді. LEFT JOIN дәл осылай жұмыс істейді: сол жақ кестенің барлық жолын сақтайды. Оң жақта сәйкесі болмаса, оның бағандары NULL болады. Ал INNER JOIN мұндай «келмеген оқушыны» тізімнен алып тастар еді.

Мысал: клиенттер мен олардың тапсырыстары

customers: 1 Айгерім, 2 Нұрлан, 8 Бауыржан. orders: 101 (клиент 1), 102 (клиент 2), 103 (клиент 1).

SELECT c.name, o.id AS order_id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id;

Бауыржанның тапсырысы жоқ, бірақ ол нәтижеде қалды, ал order_id бос. INNER JOIN болса, бұл жол мүлдем болмас еді.

Бұл «ешқашан тапсырыс бермеген клиенттер» сияқты сұрақтарға жауап береді: NULL қалған жолдарды WHERE o.id IS NULL арқылы сүземіз. Жоғарыдағы мысалда тек Бауыржан қалады.

Әр клиенттің тапсырыс санын GROUP BY арқылы есептесек, екі әдістің айырмашылығы көрінеді:

JOIN-дарды тізбектеп жазуға болады: тапсырыс → клиент, тапсырыс → позициялар → тауар. Әр жаңа JOIN өз ON шартымен бұрын қосылған кестеге жалғанады:

12. Subquery, EXISTS, ANY және ALL

«Орташадан қымбат тауарлар қайсы?» деген сұрақты екі қадаммен шешесіз: алдымен орташаны есептеп, қағазға жазып қоясыз, сосын сол санмен салыстырасыз. Subquery — сұрау ішіндегі сұрау. Ол осы «қағаздағы санды» SQL-дің өзіне есептетеді. Subquery әрқашан жақшаға алынады, ал SQL алдымен ішкі сұрауды орындайды.

Бір мән қайтаратын subquery

Төрт тауар: Құлаққап 25000, Рюкзак 15000, Термос 9000, Блокнот 1200.

SELECT name, price FROM products
WHERE price > (SELECT AVG(price) FROM products);

1-қадам: ішкі сұрау (25000 + 15000 + 9000 + 1200) / 4 = 12550 береді. 2-қадам: сұрау WHERE price > 12550 болып орындалады:

nameprice
Құлаққап25000
Рюкзак15000

Неге 12550 санын қолмен жазбаймыз? Деректер өзгергенде орташа да өзгереді, ал subquery әр жолы жаңадан есептейді.

Тізім қайтаратын subquery + IN

SELECT name FROM customers
WHERE id IN (SELECT customer_id FROM orders WHERE status = 'cancelled');

Ішкі сұрау бас тартылған тапсырыстардың клиенттерін береді: (3, 10). Сыртқы сұрау WHERE id IN (3, 10) болып, Дана мен Арманды шығарады. Ішкі сұраудағы WHERE кез келген шарт бола алады: =, BETWEEN, күн бойынша LIKE т.б.

EXISTS

EXISTS ішкі сұрау кемінде бір жол тапса, ақиқат болады. NOT EXISTS — керісінше:

SELECT p.name FROM products p
WHERE NOT EXISTS (SELECT 1 FROM order_items oi WHERE oi.product_id = p.id);

Мұнда ішкі сұрау әр тауар үшін қайта орындалады, өйткені ол сыртқы p.id-ге сілтейді. Ноутбук (id 1) үшін order_items-та жол табылады → EXISTS ақиқат → NOT EXISTS жалған, Ноутбук шықпайды. Үстел шамы (id 11) ешбір тапсырыста жоқ → ол нәтижеге кіреді. SELECT 1 — «не қайтарғаны маңызды емес, тек жол бар ма» дегенді білдіреді.

ANY және ALL

PostgreSQL сияқты дерекқорларда price > ALL (SELECT ...) «барлығынан үлкен», price > ANY (...) «кемінде біреуінен үлкен» дегенді білдіреді. Біздің браузердегі SQLite оларды қолдамайды, бірақ мағынасы бірдей жазу бар: > ALL = > (SELECT MAX(...)), > ANY = > (SELECT MIN(...)).

Жиі қателер

  • Көп мәнді > немесе =-мен салыстыру. Ішкі сұрау тізім қайтарса, IN керек. SQLite бұл жағдайда қате бермей, жай бірінші мәнді алады — нәтиже үнсіз бұрыс болады.
  • NOT IN және NULL. Ішкі тізімде бір NULL болса, NOT IN бос нәтиже береді. Мұндайда NOT EXISTS қауіпсізірек.
  • IN ішінде бірнеше баған. id IN (SELECT customer_id, order_date ...) қате — IN үшін ішкі сұрау бір баған қайтаруы керек.

14. Транзакциялар, VIEW және рұқсаттар

Транзакция (TCL)

Транзакция — бірге орындалуы керек командалар тобы. Мысалы аударымда бір шоттан ақша алынып, екіншіге түсуі керек: біреуі ғана орындалса, ақша жоғалады.

BEGIN;
UPDATE accounts SET balance = balance - 5000 WHERE id = 1;
UPDATE accounts SET balance = balance + 5000 WHERE id = 2;
COMMIT;      -- өзгерістерді бекіту

ROLLBACK — транзакция басынан бергі өзгерістерді болдырмау. SAVEPOINT name — ішкі белгі, оған дейін ROLLBACK TO name арқылы қайтуға болады.

VIEW

VIEW — сақталған сұрау. Ол кесте сияқты оқылады, бірақ дерек сақтамайды:

CREATE VIEW big_orders AS
SELECT * FROM order_items WHERE quantity >= 3;

SELECT * FROM big_orders;

Рұқсаттар (DCL)

Серверлік дерекқорларда (PostgreSQL, MySQL) кім не істей алатынын GRANT және REVOKE басқарады:

GRANT SELECT ON orders TO analyst;
REVOKE DELETE ON orders FROM analyst;

SQLite файлдық дерекқор болғандықтан, бұл командалар мұнда жоқ. Аналитикке әдетте тек SELECT рұқсаты беріледі.

ACID: транзакцияның төрт кепілдігі

  • Atomicity (бөлінбейтіндік): транзакциядағы командалар не бәрі орындалады, не ешқайсысы.
  • Consistency (тұтастық): транзакциядан кейін дерек барлық шектеулерге (constraints) сай болады.
  • Isolation (оқшаулық): қатар жүрген транзакциялар бір-біріне кедергі келтірмейді.
  • Durability (тұрақтылық): COMMIT жасалған өзгеріс сервер өшіп қалса да сақталады.

VIEW қашан пайдалы?

Бір күрделі сұрауды (бірнеше JOIN, сүзгі) әріптестер жиі қолданатын болса, оны VIEW етіп сақтаңыз. Сонда бәрі бір логиканы қолданады, ал ережені өзгерту керек болса, тек VIEW-ді қайта құрасыз. Мысалы, «белсенді клиент» анықтамасын бір VIEW-ге жазсаңыз, әр есепте ол бірдей болады.

VIEW-ді жою: DROP VIEW big_orders;. Бұл астындағы кестеге әсер етпейді.

VIEW әр оқылған сайын сұрауды қайта орындайды. Ауыр есептеулер үшін кейбір дерекқорларда materialized view бар: ол нәтижені сақтап, кесте сияқты жылдам оқылады, бірақ оны мезгіл-мезгіл жаңарту керек.
