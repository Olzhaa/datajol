M7.1 Career & Portfolio: Мансап, резюме және сұхбатқа дайындық

Білімді жұмысқа айналдыру: портфолио, резюме, LinkedIn, SQL және кейс сұхбаттары, take-home және алғашқы 90 күн. Қазақстанда алғашқы data жұмысын іздейтін адамға арналған нақты қадамдар.

Тапсырмаларды орындау

1. Жұмыс нарығы және data рөлдері

«Data маманы» деген бір мамандық емес. Вакансияларда әр түрлі рөлдер кездеседі, ал junior деңгейде олардың талаптары бір-біріне жақын.

Қазақстандағы нарық

  • Қайда іздеу: hh.kz, LinkedIn, компаниялардың career беттері, кәсіби Telegram арналары мен қауымдастықтар.
  • Кім жалдайды: банктер мен финтех, телеком, e-commerce және маркетплейстер, ритейл, логистика, мемлекеттік цифрлық сервистер, IT-компаниялар.
  • Тіл: вакансия мәтіндері жиі орыс не ағылшын тілінде жазылады. Сол тілдердегі терминдерді біліп, сұхбатқа дайын болыңыз.

Жалақы мен сұраныс туралы дайын сандарға сенбеңіз: hh.kz-тегі нақты вакансиялардан өзіңіз жинап, медианасын қараңыз. Бұл да кішкентай data жобасы.

Қадамдап мысал: вакансияны оқу

Мәтін: «Junior аналитик. SQL (JOIN, оконные функции), Excel, Power BI будет плюсом, понимание A/B тестов, умение объяснять результаты бизнесу».

  1. Міндетті: SQL оның ішінде window functions, Excel.
  2. Артықшылық: Power BI («будет плюсом»).
  3. Рөл түрі: A/B тест айтылған, демек Product Analyst-қа жақын.
  4. Әрекет: резюмеде SQL window functions және A/B тест жобасын жоғары қоямыз.
Жиі қателер: (1) тек «Data Scientist» вакансияларына өтініш беру, ал junior DS орны аз; DA мен BI жолы жиі жеңілірек кіру нүктесі. (2) «Әлі дайын емеспін» деп күту: талаптардың 60–70%-ына сәйкес келсеңіз, өтініш беріңіз. (3) Бір резюмені бәріне өзгертпей жіберу.

2. Портфолио: 2–3 жоба және README

Тәжірибесі жоқ junior-дың басты дәлелі — портфолио. Он жартылай жоба емес, 2–3 аяқталған жоба жақсы. Жұмыс беруші әр жобаға 1–2 минут бөледі, сондықтан README бірінші экранда бәрін айтуы керек.

Жобаларды таңдау

  • SQL + бизнес сұрақ: мысалы, онлайн дүкеннің retention немесе воронка талдауы.
  • Дашборд: Power BI не Looker Studio-да метрикалар беті, скриншотымен.
  • Python талдау: ашық деректерді тазалау, EDA, A/B тест не болжам.

Деректер ашық болсын (Kaggle, data.egov.kz сияқты ашық порталдар, өзіңіз жинаған hh.kz вакансиялары). Бөгде компанияның құпия деректерін жарияламаңыз.

README құрылымы

  1. Сұрақ: қандай бизнес мәселені шештіңіз?
  2. Деректер: қайдан, қанша жол, қай кезең, шектеулері.
  3. Әдіс: қандай қадамдар (тазалау, SQL, A/B тест), қысқаша.
  4. Нәтиже: 2–3 негізгі тұжырым сандармен.
  5. Ұсыныс: бизнес не істеуі керек және келесі қадам.

Ұсыныс: бірінші тапсырыстан кейін 14 күнде промокод жіберу,

Әр жобаны бір-бірінен ерекшелеңіз: біреуі SQL күшін, біреуі визуализация мен дашбордты, біреуі Python мен статистиканы көрсетсін. Сонда үш жоба бірге «толық junior аналитик» бейнесін береді. Жобаның атауы да маңызды: «project1» емес, «Онлайн дүкен: retention талдауы» сияқты мағыналы атау қойыңыз.

Байқаңыз: оқырман бірінші бес жолдан-ақ не табылғанын біледі. Код пен графиктер төменде, «Әдіс» бөлімінен кейін.

Жиі қателер: (1) README жоқ немесе тек «Kaggle titanic notebook». (2) Нәтиже сансыз: «қызықты заңдылықтар таптым». (3) Ұсыныс жоқ, ал аналитиктің құндылығы — шешімге көмектесу. (4) Курс тапсырмасын өзгертпей көшіру: кемінде сұрақты өзіңізше қойыңыз.

3. Data рөліне резюме

Резюме — сұхбатқа шақыру алу құралы. Recruiter оны алғашында бірнеше секунд қарайды, ал көп компания ATS (Applicant Tracking System) жүйесін қолданады: ол резюмедегі кілт сөздерді вакансиямен салыстырады.

Құрылым (бір бет)

  1. Аты-жөні, қала, телефон, email, LinkedIn, GitHub/портфолио сілтемесі.
  2. Қысқа summary (2 жол): кім екеніңіз және не істей аласыз.
  3. Skills: SQL, Python (pandas), Excel, Power BI, статистика, A/B тест.
  4. Projects (тәжірибе аз болса, жобалар жоғарыда).
  5. Experience (кез келген жұмыс, тағылымдама, фриланс), Education, тілдер.

Impact bullet

Формула: етістік + не істедіңіз + құрал + нәтиже санмен. Нәтиже — салыстыру: «X-тен Y-ке», «N сағат үнемдеді», «M клиент сегментін тапты».

5. SQL сұхбаты I: екінші ең жоғары жалақы және дубликаттар

Junior сұхбатындағы SQL тапсырмалары жиі қайталанады. Олардың «классикалық» үлгілерін біліп, ойыңызды дауыстап айтуды жаттықтырыңыз. Дерекқор: staff, кесте employees(id, name, department, salary, hire_date, manager_id).

1. Екінші ең жоғары жалақы

Ең танымал сұрақ. Екі тәсіл бар:

-- (а) ішкі сұрау: максимумнан кіші мәндердің максимумы
SELECT MAX(salary) AS second_salary
FROM employees
WHERE salary < (SELECT MAX(salary) FROM employees);

-- (ә) DISTINCT + LIMIT/OFFSET
SELECT DISTINCT salary FROM employees
ORDER BY salary DESC LIMIT 1 OFFSET 1;

Қадамдап мысал

  1. Нақтылаңыз: «Екі адамның жалақысы бірдей ең жоғары болса, екінші орын кім?» Интервьюер дәл осы сұрақты күтеді.
  2. Ішкі сұрау: SELECT MAX(salary) → 1 200 000.
  3. Сыртқы сұрау: 1 200 000-нан кіші мәндердің максимумы → 900 000.
  4. Шеттік жағдай: тек бір қызметкер болса, (а) NULL қайтарады, (ә) бос кесте. Осыны айтыңыз.

2. Дубликаттарды табу

«Қай мәндер бірнеше рет кездеседі?» — GROUP BY + HAVING:

SELECT department, salary, COUNT(*) AS cnt
FROM employees
GROUP BY department, salary
HAVING COUNT(*) > 1;

Нағыз деректе дубликат — бірдей email не бірдей тапсырыс жолы. Логика сол: топтау кілтін таңдап, COUNT(*) > 1.

Бір ескерту: бұл сұрауда department және salary бойынша топтадық, яғни «бір бөлімде бірдей жалақы алатындар». Тек salary бойынша топтасаңыз, әр түрлі бөлімдегі адамдар да бір топқа түседі. Топтау кілтін таңдау — тапсырманы нақтылаудың бөлігі.

Сұхбатта қалай сөйлеу

  • Кестені, бағандарды және нәтиженің пішінін нақтылаңыз.
  • Қарапайым шешімнен бастаңыз, сосын шеттік жағдайларды (NULL, тең мәндер) атаңыз.
  • Нәтижені кішкене мысалмен тексеріңіз.
Жиі қателер: (1) ORDER BY salary DESC LIMIT 1 OFFSET 1 — DISTINCT-сіз тең жалақылар болса, қате нәтиже береді; (2) WHERE COUNT(*) > 1 — агрегатқа шарт HAVING-та; (3) сұрақты нақтыламай бірден жазу.

6. SQL сұхбаты II: top-N әр топта және retention

Екінші деңгейдегі сұрақтар window functions пен когорттарды тексереді. Product Analyst сұхбатында retention сұрағы жиі кездеседі.

Top-N әр топта

«Әр бөлімдегі ең жоғары жалақы алатын 2 адам» — GROUP BY бұны жасай алмайды, себебі ол жолдарды біріктіреді. Window function жолдарды сақтап, әр топ ішінде нөмір береді:

ФункцияТең мәндер (520, 520)
ROW_NUMBER()1, 2, 3 — тең мәндерге әр түрлі нөмір
RANK()1, 2, 2, 4 — секіріс бар
DENSE_RANK()1, 2, 2, 3 — секіріссіз
SELECT department, name, salary
FROM (
  SELECT department, name, salary,
         DENSE_RANK() OVER (PARTITION BY department ORDER BY salary DESC) AS rnk
  FROM employees
)
WHERE rnk <= 2;

Window function нәтижесін WHERE-де тікелей қолдануға болмайды, сондықтан ішкі сұрау (не CTE) керек.

Retention: қадамдап мысал

Дерекқор metrics: users(id, signup_month, channel), activity(user_id, month). Сұрақ: «Әр когорттың неше пайызы келесі айда белсенді болды?»

  1. Когорт = тіркелген ай. Шілде когорты: 1, 2, 3, 4 (4 адам).
  2. Келесі ай: strftime('%Y-%m', signup_month || '-01', '+1 month') → «2024-08».
  3. LEFT JOIN activity осы шартпен: тамызда белсенді болғандар 1, 2, 4 → 3 адам.
  4. Retention = 3 / 4 = 75%.
SELECT u.signup_month,
       COUNT(DISTINCT u.id) AS cohort_size,
       COUNT(DISTINCT a.user_id) AS retained
FROM users u
LEFT JOIN activity a
  ON a.user_id = u.id
 AND a.month = strftime('%Y-%m', u.signup_month || '-01', '+1 month')
GROUP BY u.signup_month;

LEFT JOIN маңызды: ешкім қайтпаған когорт та нәтижеде 0-мен көрінуі керек.

Жиі қателер: (1) тең мәндер туралы сұрамай ROW_NUMBER алу; (2) шартты ON орнына WHERE-ге жазу — сонда LEFT JOIN INNER JOIN-ға айналады; (3) COUNT(*) алу, ал JOIN-нан кейін жолдар көбейіп кетуі мүмкін, COUNT(DISTINCT ...) сенімдірек; (4) бүтін санды бөлу: 100.0 * қосыңыз.

7. Python/pandas take-home: тапсырманы қалай орындау

Take-home — үйде орындалатын тапсырма: CSV файл және 3–5 сұрақ, мерзімі 2–7 күн. Мұнда тек дұрыс жауап емес, жұмыстың тазалығы мен түсініктілігі бағаланады.

Notebook құрылымы

  1. Мақсат: тапсырманың сұрақтарын өз сөзіңізбен қайталау.
  2. Жүктеу және тексеру: df.shape, df.info(), df.isna().sum(), df.duplicated().sum().
  3. Тазалау: әр ережені жазыңыз (неге және қанша жол әсер етті).
  4. Талдау: әр сұраққа бөлек бөлім, қысқа қорытындымен.
  5. Қорытынды: жауаптар, ұсыныстар, шектеулер, болжамдар (assumptions).

Қадамдап мысал

import pandas as pd
df = pd.read_csv('orders.csv')
print(df.shape)                      # (10 250, 5)
print(df.duplicated('order_id').sum())   # 250 дубликат
df = df.drop_duplicates('order_id')
df = df[df['status'] != 'cancelled']
df = df.dropna(subset=['amount'])
assert df['order_id'].is_unique, 'order_id қайталанбауы керек'
by_city = df.groupby('city')['amount'].sum().sort_values(ascending=False)
  1. Өлшемін көрдік → дубликаттарды санадық.
  2. Әр тазалау қадамынан кейін қанша жол қалғанын жазамыз.
  3. assert — өзіңізді тексеру: интервьюер мұны жақсы белгі деп санайды.
  4. Нәтижені бір сөйлеммен түсіндіреміз: «Табыстың 45%-ы Алматыдан».

Тапсырманы жібергенде қысқа ілеспе хат жазыңыз: негізгі 3 жауап, қолданған болжамдарыңыз және notebook-ты қалай іске қосу керек. Тексеруші жұмысыңызды ашпай тұрып-ақ нәтижені көреді. Көп компанияда take-home-нан кейін оны талқылау кезеңі болады: «неге осы тәсілді таңдадыңыз?», «тағы уақыт болса не істер едіңіз?» деген сұрақтарға жауапты алдын ала ойлаңыз. Pandas-ты білмесеңіз де, логика бірдей: дубликат, бос мән, сүзгі, топтау. Төмендегі тапсырмада сол логиканы стандарт Python-да жазасыз.

Жалпы кеңестер

  • Уақытты шектеңіз: тапсырма «3–4 сағат» десе, 2 күн жұмсамаңыз. Не істемегеніңізді «Келесі қадамдар» бөлімінде жазыңыз.
  • Болжамдарды айтыңыз: «cancelled тапсырыстарды табысқа қоспадым».
  • Қайталанатын: notebook басынан аяғына дейін қатесіз жүруі керек; requirements.txt қосыңыз.
  • Код таза: функциялар, түсінікті атаулар, артық шығаруларсыз.
Жиі қателер: (1) тазалауды түсіндірмей жасау; (2) 40 график, бірақ сұраққа жауап жоқ; (3) ML модельді сұралмаса да қосу; (4) notebook-ты ретсіз іске қосылған күйде жіберу.

8. Кейс сұхбаты: метрика 10% түсті

Product sense не кейс сұхбатында сізге ашық сұрақ қояды: «Кеше табыс 10% төмендеді. Қалай зерттейсіз?» Бір «дұрыс жауап» жоқ, бағаланатыны — құрылымды ойлау.

Бес қадамды фреймворк

  1. Нақтылау: қай метрика, қай кезеңмен салыстырғанда (кеше vs алдыңғы күн, vs өткен аптаның сол күні)? 10% қалыпты ауытқудан тыс па?
  2. Деректі тексеру: трекинг, ETL кешігуі, толық емес күн, жаңа релиз, дашборд қатесі.
  3. Ішкі/сыртқы себептер: мереке, маусымдылық, бәсекелес акциясы, төлем жүйесінің ақауы.
  4. Декомпозиция: метриканы бөліктерге бөліңіз: табыс = қолданушылар × конверсия × орташа чек. Сосын сегменттер: аймақ, платформа (iOS/Android/web), арна, жаңа/қайталама клиент.
  5. Гипотеза → тексеру → ұсыныс: құлдырау қай сегментте шоғырланған, неге, не істеу керек.

Қадамдап мысал

Дерекқор metrics, кесте daily_sales(day, region, revenue). Күндік жалпы табысты алдыңғы күнмен LAG арқылы салыстырамыз:

WITH t AS (
  SELECT day, SUM(revenue) AS revenue FROM daily_sales GROUP BY day
)
SELECT day, revenue,
       LAG(revenue) OVER (ORDER BY day) AS prev_revenue
FROM t;
  1. 2024-09-07: 315, 2024-09-08: 250. Өзгеріс −65, яғни шамамен −20.6%.
  2. Аймаққа бөлеміз: Алматы 190 → 140 (−50), Астана 125 → 110 (−15).
  3. Құлдыраудың 50 / 65 ≈ 77%-ы Алматыдан. Келесі сұрақ: Алматыда не болды? (жеткізу, акция аяқталды ма, қай платформа?)
  4. Келесі күні табыс 295-ке қайтты: бір күндік ауытқу болуы мүмкін, бірақ себебін тексеру керек.

Сұхбатта осы қадамдарды дауыстап айтып, әр қадамда қандай дерек сұрар едіңіз, соны атаңыз. Интервьюер көбіне жаңа ақпарат береді («Android-та ғана түсті»), сонда фреймворкты сол бағытқа бұрасыз.

Жиі қателер: (1) бірден себеп айту («маркетинг нашар»); (2) деректің дұрыстығын тексермеу; (3) сегменттерге бөлмей, жалпы санмен ғана қорытынды жасау; (4) аптаның күнін ескермеу: жексенбіні сенбімен салыстыру әділ емес; (5) соңында ұсыныс пен келесі қадамды айтпау.

9. Мінез-құлық сұхбаты: STAR әдісі

Техникалық бөлімнен бөлек, әр компания «сіз қалай жұмыс істейсіз?» дегенді сұрайды: «Қиын жағдай туралы айтыңыз», «Қателескен кезіңіз», «Келіспеушілікті қалай шештіңіз?». Мұндай сұраққа STAR құрылымымен жауап беріңіз. Ол жауапты қысқа, ретті және дәлелді етеді, ал интервьюерге сіздің нақты үлесіңізді көруге көмектеседі.

ӘріпМағынасыҮлесі
SituationЖағдай: қашан, қайда, қандай контекст~15%
TaskСіздің міндетіңіз не еді~10%
ActionСіз нақты не істедіңіз (мен, біз емес)~50%
ResultНәтиже санмен және не үйрендіңіз~25%

Қадамдап мысал

Сұрақ: «Деректе қате тапқан кезіңіз туралы айтыңыз.»

  1. S: «Курстық жобада онлайн дүкеннің айлық табыс есебін дайындадым, қорғауға екі күн қалды.»
  2. T: «Есеп сандары дұрыс екеніне мен жауапты едім.»
  3. A: «Тапсырыс санын бастапқы файлмен салыстырып, 3%-ға артық екенін байқадым. JOIN-нан кейін жолдар көбейгенін тауып, COUNT(DISTINCT order_id)-ға ауыстырдым және әр қадамнан кейін жол санын тексеретін assert қостым.»
  4. R: «Табыс 3%-ға түзетілді, есеп уақытында тапсырылды. Содан бері әр JOIN-нан кейін жол санын тексеремін.»

Байқаңыз: Result тек «бәрі жақсы болды» емес, нақты факт (3%-ға түзетілді, уақытында тапсырылды) және сабақ (енді әр JOIN-нан кейін тексеремін). Сабақ бөлігі интервьюерге сіздің өсетініңізді көрсетеді.

Дайындық

  • 5–6 оқиға дайындаңыз: қиын тапсырма, қателік, келіспеушілік, қысқа мерзім, өз бастамаңыз, жаңа нәрсені тез үйрену.
  • Тәжірибе аз болса: оқу жобалары, волонтерлік, бұрынғы кез келген жұмыс та жарайды.
  • Әр жауап 1.5–2 минут. Дауыстап айтып, жазып алып тыңдаңыз.
  • Соңында сіз де сұрақ қойыңыз: «Junior аналитиктің алғашқы 3 айда табысты болғаны қалай өлшенеді?»
Жиі қателер: (1) Action-да тек «біз» — интервьюер сіздің үлесіңізді білгісі келеді; (2) нәтижесіз аяқтау; (3) 5 минуттық ұзақ әңгіме; (4) «қателеспеймін» деу: шынайы қателік пен одан алған сабақ әлдеқайда күшті.

10. Оффер, жалақы және алғашқы 30-60-90 күн

Сұхбаттан өттіңіз — енді офферді дұрыс бағалап, алғашқы айларда жақсы әсер қалдыру керек.

Жалақы және оффер негіздері

  • Нарықты біліңіз: hh.kz-те ұқсас junior вакансиялардың жалақы ауқымын жинап, медианасын табыңыз. Ойдан сан айтпаңыз.
  • «На руки» немесе «до вычета»: айтылған сома салықтар мен міндетті жарналардан бұрын ба, кейін бе — міндетті түрде нақтылаңыз.
  • Толық пакет: ай жалақысы × 12 + жылдық бонус + медициналық сақтандыру, оқу бюджеті, remote/гибрид, сынақ мерзімі (испытательный срок).
  • Келіссөз: алғаш болып ауқымды сұрағанда, нарық деректеріне сүйеніп ауқым айтыңыз. Офферге бірден «иә» деудің орнына 1–2 күн ойлануға сұрау қалыпты.
  • Жазбаша растау: лауазым, жалақы, бастау күні, сынақ мерзімі жазбаша болсын.

Қадамдап мысал: екі офферді салыстыру

  1. А: айына 450 000 ₸, бонус жоқ → жылына 450 000 × 12 = 5 400 000 ₸.
  2. Б: айына 400 000 ₸ + жылдық бонус 1 000 000 ₸ → 4 800 000 + 1 000 000 = 5 800 000 ₸.
  3. Б жылына 400 000 ₸ көп, бірақ бонус кепілдендірілген бе? Шарттарын сұраңыз.
  4. Ақшадан бөлек: қайсысында тәлімгер (mentor) мен күшті data командасы бар? Алғашқы жұмыста үйрену жылдамдығы өте маңызды.

30-60-90 күндік жоспар

КезеңМақсатНақты нәтиже
1–30 күнҮйренуДеректер қоймасы мен негізгі кестелер, метрикалар анықтамасы, командамен 1:1 кездесулер, бір кішкене тапсырманы аяқтау
31–60 күнҮлес қосуБір есепті не дашбордты өз бетімен жасау, сұраулар кітапханасын жүргізу
61–90 күнБастамаБір процесті автоматтандыру не жақсарту ұсынысы, нәтижені басшымен талқылау
Жиі қателер: (1) жалақыны «на руки» ма, жоқ па нақтыламау; (2) алғашқы аптада бәрін «қайта жасауды» ұсыну; (3) сұрақ қоюдан қорқу: алғашқы айда сұрақ қою — жұмыстың бір бөлігі; (4) метрика анықтамаларын жазбай, кейін әр түрлі сандар шығару.
