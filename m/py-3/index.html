HTTP сұрауды талдау, REST дизайны, роутер, валидация, ORM идеясы, аутентификация, тесттер, regex, асинхрондылық және деплой. Браузерде нағыз сервер жоқ, сондықтан бәрін таза Python модельдерімен жасаймыз, соңында URL қысқартқыш сервисін құрасыз.

1. Веб қалай жұмыс істейді: HTTP сұрау мен жауап

Сіз телефоннан «Тамақ жеткізу» қосымшасын ашып, Алматыдағы кофеханалар тізімін көресіз. Сол сәтте телефон (client) интернет арқылы алыстағы компьютерге (server) сұрау жібереді, ал сервер жауап қайтарады. Backend әзірлеуші дәл осы сервер жағын жазады: сұрауды қабылдайды, дерекқордан мәлімет алады, жауап құрастырады.

Software Eng курсының REST сабағында методтар мен status code кестесін көрдіңіз. Енді бір деңгей төмен түсеміз: HTTP сұрау шын мәнінде жай мәтін, оны өзіміз талдай аламыз.

Бір сұраудың жолы

  • DNS: api.kofe.kz атауы IP-мекенжайға айналады.
  • TCP байланыс (HTTPS болса, оның үстіне TLS шифрлау) ашылады.
  • Клиент HTTP сұрау мәтінін жібереді, сервер HTTP жауап мәтінін қайтарады.

Сұраудың құрылымы

GET /cafes?city=Алматы&page=2 HTTP/1.1      ← request line: method, path, нұсқа
Host: api.kofe.kz                          ← headers: "Аты: мәні"
Accept: application/json
User-Agent: KofeApp/3.1
                                           ← бос жол: headers бітті
(GET-те body әдетте болмайды)

Жолдар \r\n (CRLF) арқылы бөлінеді, ал headers пен body арасында бос жол тұрады, яғни \r\n\r\n. Path ішіндегі ? белгісінен кейінгі бөлік query string: city=Алматы&page=2.

Жиі кездесетін headers

HeaderНе үшін
Content-Typebody қандай форматта: application/json, text/html
Content-Lengthbody ұзындығы байтпен
Authorizationкім сұрап тұр: Bearer <token>

Header атаулары регистрге тәуелсіз: content-type мен Content-Type бірдей. Сондықтан талдағанда атауды кіші әріпке келтіру ыңғайлы.

Python-да сұрауды талдау

raw = "POST /orders HTTP/1.1\r\nHost: api.kofe.kz\r\nContent-Type: application/json\r\n\r\n{\"drink\": \"latte\"}"
head, body = raw.split("\r\n\r\n", 1)
lines = head.split("\r\n")
method, path, version = lines[0].split(" ")
headers = {}
for line in lines[1:]:
    name, value = line.split(":", 1)
    headers[name.strip().lower()] = value.strip()
print(method, path, headers["content-type"], body)

Жауап та осындай: бірінші жолда HTTP/1.1 201 Created, сосын headers, бос жол және body. Status code бірінші цифрына қарап топталады: 1xx ақпарат, 2xx сәтті, 3xx қайта бағыттау (redirect), 4xx клиент қатесі, 5xx сервер қатесі.

Жиі қателер

  • split(":") шектеусіз шақыру: Host: localhost:8000 мәнінде қос нүкте тағы бар. split(":", 1) жазыңыз.
  • Content-Length таңба санымен есептеу: «Алматы» 6 таңба, бірақ UTF-8-де 12 байт.
  • Body-ді "\n\n" бойынша іздеу: HTTP-де бөлгіш "\r\n\r\n".

Сервер жағынан бір сұрауды өңдеу әрқашан үш қадам: мәтінді талдау (parse), бизнес логиканы орындау және жауап мәтінін құрастыру. Осы модульде біз үшеуін де бөлек функция ретінде жазамыз, ал соңында оларды бір сервиске жинаймыз.

Flask, FastAPI, Django сияқты фреймворктар осы талдауды сіз үшін жасайды да, дайын request объектісін береді. Бірақ қате шыққанда (мысалы, 400 Bad Request) астында не болып жатқанын білу өте көмектеседі.

2. Debugging және код стилі: traceback, PEP 8, docstring

Backend кодының көп бөлігі «неге жұмыс істемейді?» деген сұраққа жауап іздеумен өтеді. Қатені тез табу дағдысы жаңа синтаксис білуден кем маңызды емес. Ал таза стиль қатенің аз болуына көмектеседі.

Traceback-ті төменнен жоғары оқу

Traceback (most recent call last):
  File "app.py", line 14, in <module>
    print(order_total(cart))
  File "app.py", line 9, in order_total
    total += item["price"] * item["qty"]
KeyError: 'qty'
  • Ең төменгі жол: қатенің түрі мен себебі. Мұнда KeyError: 'qty', яғни бір тауарда qty кілті жоқ.
  • Оның үстінде: қате қай жолда болды (line 9, in order_total).
  • Одан жоғары: бұл функцияны кім шақырды. Тізбек «шақыру стегі» (call stack) деп аталады.

Жиі кездесетін түрлер: TypeError (тип сәйкес емес, мысалы "#" + 5), KeyError, IndexError, AttributeError (None объектісінде әдіс жоқ), ZeroDivisionError.

print және breakpoint

Ең қарапайым тәсіл: күдікті жерге print(f"{item=}") қою. = белгісі айнымалының атын да шығарады: item={'name': 'latte'}. Күрделірек жағдайда breakpoint() жазасыз: бағдарлама сол жерде тоқтап, pdb debugger ашылады.

Браузердегі Python-да интерактивті debugger жоқ, сондықтан мұнда print қолданамыз. VS Code пен PyCharm-да нүктені жол нөмірінің жанына қойып, дәл осындай тоқтауды тышқанмен жасайсыз.

PEP 8: ортақ стиль

MAX_ITEMS = 50                      # константа: UPPER_CASE

class OrderService:                 # класс: CamelCase
    def total_price(self, items):   # функция, айнымалы: snake_case
        """Тауарлардың жалпы бағасын теңгемен қайтарады."""
        return sum(i["price"] * i["qty"] for i in items)
  • Шегініс: 4 бос орын, tab емес. Жол ұзындығы шамамен 79-99 таңба.
  • Операторлар айналасында бос орын: x = a + b, бірақ f(a=1) ішінде бос орынсыз.
  • import файлдың басында. Атаулар мағыналы: d емес, delivery_fee.

Docstring

Функцияның бірінші жолындағы үш тырнақшалы мәтін docstring деп аталады. Ол func.__doc__ және help(func) арқылы оқылады. Жақсы docstring функция не істейтінін, параметрлерін, қайтаратын мәнін және қандай қате шығаратынын айтады.

Жиі қателер

  • Traceback-тің тек жоғарғы жолын оқып, нақты себепті (ең төменгі жол) өткізіп алу.
  • Әдепкі мән ретінде [] беру: тізім барлық шақыруда ортақ болады.
  • Debug үшін қойған print-терді кодта қалдырып кету. Production-да logging қолданыңыз (Software Eng курсында өттік).
Қатені түзетпес бұрын оны қайталап шығаратын ең кішкентай мысалды табыңыз. Мысал 3 жолға дейін қысқарса, себеп әдетте өзі көрініп тұрады.

3. REST API дизайны: ресурстар, CRUD, пагинация

Жақсы API-ды бір рет көрген әзірлеуші қалған endpoint-терді өзі болжай алады. REST дизайнының мәні осында: бәрі ресурс (зат есім), ал әрекетті HTTP метод айтады.

Атаулар

  • Ресурс көпше түрде, зат есім: /products, /orders. /getProducts немесе /createOrder емес.
  • Бір объект: /products/42. Кіріктірілген ресурс: /shops/3/orders (3-дүкеннің тапсырыстары).
  • Кіші әріп, сөздер дефиспен: /gift-cards. Нұсқа алдында: /v1/products.
  • Сүзгі мен сұрыптау query string-те: /products?city=Алматы&sort=-price.

CRUD және методтар

ЖасауPOST /products201 + жаңа объект (және Location header)

Кілттер бір стильде болсын (әдетте snake_case немесе camelCase, араластырмаңыз). Күн мен уақыт ISO форматта: "2026-03-21T12:30:00+05:00". Ақша бүтін санмен (тиынмен немесе теңгемен), float-пен емес.

Идемпотенттілік

Мобильді интернет үзіліп, клиент бір сұрауды қайта жіберді делік. PUT және DELETE идемпотентті: қайталау нәтижені өзгертпейді. POST қайталанса, екі тапсырыс жасалып, клиенттен екі рет ақша алынуы мүмкін. Сондықтан төлем API-лары Idempotency-Key header-ін сұрайды: сервер кілтті есте сақтап, қайталанған сұрауға бұрынғы жауапты қайтарады.

Пагинация

10 000 тауарды бір жауапта жіберу баяу. Екі тәсіл бар:

  • Page/offset: ?page=2&per_page=20. Қарапайым, бірақ тізім өзгеріп жатса, элементтер қайталанып не жоғалып кетуі мүмкін.
  • Cursor: ?after=1050&limit=20, яғни «id 1050-ден кейінгі 20 элемент». Үлкен, жылдам өзгеретін тізімге тұрақты.
def page_of(items, page, per_page):
    start = (page - 1) * per_page
    return items[start:start + per_page]

Қате жауаптың форматы

Қате болғанда да жауап бір үлгіде болсын, сонда клиент оны бір жерде өңдей алады. Мысалы: {"error": {"code": "not_found", "message": "Тауар табылмады"}}. Status code жалпы санатты айтады, ал code өрісі нақты себепті айтады. Келесі сабақтарда роутер мен валидация дәл осы үлгіні қайтарады.

Жиі қателер

  • URL-ға етістік жазу (/deleteUser/5) немесе бәрін POST арқылы жасау.
  • Қате болса да 200 қайтарып, body-де {"error": ...} жазу. Клиент status code-қа сенеді.
  • Пагинациясыз тізім: бүгін 50 жазба, бір жылдан кейін 500 000.
API-ды жазбас бұрын endpoint кестесін (метод, path, сұрау, жауап, кодтар) бір бетке жазып шығыңыз. Бұл фронтенд әзірлеушімен келісудің ең арзан жолы.

4. Роутинг: декоратормен өз роутеріңізді жазу

Сервер сұрауды талдап болды: GET /users/42. Енді қай функция жауап беруі керек? Бұл сұраққа router жауап береді. Flask-та ол былай көрінеді:

@app.route("/users/<id>", methods=["GET"])
def get_user(id):
    ...

Intermediate Python курсында декоратор функцияны қабылдап, функция қайтаратынын көрдіңіз. app.route(...) параметрлі декоратор: ол алдымен шақырылып, нағыз декораторды қайтарады, ал ол функцияны кестеге тіркейді де, өзгертпей қайтарады.

Path үлгісін сәйкестендіру

Үлгі мен path-ты / бойынша бөліктерге бөлеміз. Бөлік саны тең болуы керек. <id> түріндегі бөлік кез келген мәнді қабылдап, оны параметр ретінде сақтайды, қалғандары дәл сәйкес келуі керек.

def match(pattern, path):
    p_parts = pattern.strip("/").split("/")
    parts = path.strip("/").split("/")
    if len(p_parts) != len(parts):
        return None
    params = {}
    for p, v in zip(p_parts, parts):
        if p.startswith("<") and p.endswith(">"):
            params[p[1:-1]] = v
        elif p != v:
            return None
    return params

match("/users/<id>", "/users/42")        # {'id': '42'}
match("/users/<id>", "/users/42/orders") # None

Шағын App класы

class App:
    def __init__(self):
        self.routes = []            # (pattern, methods, handler)

    def route(self, pattern, methods=("GET",)):
        def decorator(func):
            self.routes.append((pattern, set(methods), func))
            return func
        return decorator

    def handle(self, method, path):
        path_found = False
        for pattern, methods, func in self.routes:
            params = match(pattern, path)
            if params is None:
                continue
            path_found = True
            if method in methods:
                return func(**params)
        if path_found:
            return 405, {"error": "method not allowed"}
        return 404, {"error": "not found"}

app = App()

@app.route("/cafes/<cafe_id>/menu")
def menu(cafe_id):
    return 200, {"cafe": cafe_id, "drinks": ["latte", "americano"]}

app.handle("GET", "/cafes/7/menu")    # (200, {...})
app.handle("POST", "/cafes/7/menu")   # (405, ...)
app.handle("GET", "/bus/12")          # (404, ...)

Біздің handler-лер (status, body) жұбын қайтарады. Нағыз фреймворкте де дәл осы: жауап объектісі status, headers және body-ден тұрады.

404 және 405 айырмасы

404: мұндай path мүлде жоқ. 405: path бар, бірақ бұл метод рұқсат етілмеген, мысалы тек оқуға арналған мәзірге POST. Дұрыс сервер 405 жауабына Allow: GET header-ін қосады.

Түрлендіргіштер (converters)

Flask-та <int:id> жазуға болады: бөлік тек цифр болса сәйкес келеді және int-ке айналады. Сонда /users/abc handler-ге жетпей тұрып 404 береді, ал handler ішінде int() түрлендіру қажет емес.

Жиі қателер

  • Декоратор ішінде return func ұмыту: функцияның аты None болып қалады.
  • Соңғы /: /users/42/ мен /users/42 бірдей ме? Келісіп алыңыз (біз strip("/") жасаймыз).
  • Маршрут реті: /users/me мен /users/<id> болса, нақтысын бірінші тіркеңіз, әйтпесе me id ретінде ұсталады.
FastAPI-да да идея сол: @app.get("/users/{user_id}"), ал user_id: int type hint-і түрлендіргіштің рөлін атқарады.

5. Валидация және қателер: 400, 422, өз exception-дарыңыз

Сервер ешқашан клиентке сенбеуі керек. Мобильді қосымша ескі нұсқада болуы мүмкін, біреу curl арқылы кез келген мәтін жібере алады. Сондықтан әр кіріс дерек валидациядан өтеді, ал қате болса, клиент не дұрыс емес екенін нақты біледі.

400 пе, әлде 422 ме?

  • 400 Bad Request: сұрауды мүлде оқу мүмкін емес. Мысалы, JSON бұзық: {"name": "Дана",.
  • 422 Unprocessable Entity: JSON дұрыс оқылды, бірақ мәндері ережеге сай емес: {"age": -5}.

Кей командалар екеуіне де 400 қолданады. Маңыздысы: бір API ішінде бірізді болу және қатені түсінікті body-мен қайтару.

Қате body: өріс бойынша

422 Unprocessable Entity
{"errors": {"email": "email форматы қате", "age": "18-ден үлкен болуы керек"}}

Барлық қатені бір рет жинап қайтарған дұрыс: пайдаланушы форманы бір рет түзетеді, бес рет емес.

dataclass: сұрау моделі

dataclass __init__, __repr__, __eq__ әдістерін өзі жазады. Бұл FastAPI-дағы Pydantic модельдерінің қарапайым нұсқасы.

import json
from dataclasses import dataclass, asdict

@dataclass
class SignupRequest:
    name: str
    age: int
    city: str = "Алматы"

def validate_signup(data):
    errors = {}
    name = data.get("name")
    if not isinstance(name, str) or not name.strip():
        errors["name"] = "аты міндетті"
    age = data.get("age")
    if not isinstance(age, int) or isinstance(age, bool) or age < 14:
        errors["age"] = "жасы 14-тен кем емес бүтін сан"
    return errors

def signup(raw_body):
    try:
        data = json.loads(raw_body)
    except json.JSONDecodeError:
        return 400, {"error": "JSON оқылмады"}
    if not isinstance(data, dict):
        return 400, {"error": "JSON объект күтілді"}
    errors = validate_signup(data)
    if errors:
        return 422, {"errors": errors}
    req = SignupRequest(data["name"].strip(), data["age"], data.get("city", "Алматы"))
    return 201, asdict(req)

Назар аударыңыз: isinstance(True, int) Python-да True, себебі bool int-тің ұрпағы. Сондықтан bool-ды бөлек тексереміз.

Өз exception класстарыңыз

Терең функциялардан (status, body) қайтарып, оны жоғары қарай тасу ыңғайсыз. Оның орнына exception шығарып, бір жерде ұстаймыз:

class ApiError(Exception):
    status = 500
    def __init__(self, message):
        super().__init__(message)
        self.message = message

class NotFound(ApiError):
    status = 404

class Conflict(ApiError):
    status = 409

def safe(handler):
    def wrapper(*args, **kwargs):
        try:
            return handler(*args, **kwargs)
        except ApiError as e:
            return e.status, {"error": e.message}
    return wrapper

Енді handler ішінде жай ғана raise NotFound("кофехана табылмады") жазасыз, ал safe декораторы оны дұрыс жауапқа айналдырады. Flask-та бұл @app.errorhandler, FastAPI-да HTTPException.

Жиі қателер

  • Бірінші қатеде тоқтап, қалғандарын айтпау.
  • except Exception арқылы бәрін ұстап, 200 қайтару: нағыз bug-тар жасырынып қалады.
  • Қате хабарламасында ішкі мәліметті (SQL, traceback, құпия сөз) көрсету.
Валидацияны шекарада (сұрау кірген жерде) бір рет жасаңыз. Ішкі функциялар таза, тексерілген деректермен жұмыс істесін.

6. ORM идеясы: модельдер, repository, N+1

SQL курсында кестелерге SELECT, INSERT сұрауларын тікелей жаздыңыз. Backend-те әр handler-ге SQL жолын жазу тез шаршатады және қате көп. ORM (Object-Relational Mapping) кестені класқа, жолды объектіге айналдырады: SQLAlchemy, Django ORM, Peewee.

Модель = кесте, объект = жол

# Django стилі (түсіну үшін)
class Cafe(models.Model):
    name = models.CharField(max_length=100)
    city = models.CharField(max_length=50)
    rating = models.FloatField()

Cafe.objects.filter(city="Астана").order_by("-rating")[:5]
# SELECT * FROM cafe WHERE city = 'Астана' ORDER BY rating DESC LIMIT 5

Соңғы жол SQL-ге айналады. Маңызды ерекшелік: filter мен order_by сұрауды бірден орындамайды, тек QuerySet құрастырады. Дерекқорға нәтиже шынымен керек болғанда (цикл, list(), len()) ғана барады. Бұл lazy есептеу.

Жадтағы repository

ORM-ның ішкі идеясын түсіну үшін оны тізімнің үстіне жазайық. Repository үлгісі деректі сақтау тәсілін жасырады: handler repo.get(5) шақырады, ал астында SQLite ма, PostgreSQL ма, жай тізім бе, оған бәрібір. Тесттерде жадтағы нұсқасын қолдану сондықтан ыңғайлы.

from dataclasses import dataclass

@dataclass
class Cafe:
    name: str
    city: str
    rating: float
    id: int = None

class Repo:
    def __init__(self):
        self.rows, self.next_id = {}, 1
    def add(self, obj):
        obj.id = self.next_id
        self.rows[obj.id] = obj
        self.next_id += 1
        return obj
    def get(self, id):
        return self.rows.get(id)
    def filter(self, **kw):
        return [o for o in self.rows.values()
                if all(getattr(o, k) == v for k, v in kw.items())]

repo = Repo()
repo.add(Cafe("Kofe Bar", "Астана", 4.6))
repo.add(Cafe("Daily Cup", "Алматы", 4.8))
repo.filter(city="Алматы")    # [Cafe(name='Daily Cup', ...)]

**kw атаулы аргументтерді сөздікке жинайды, ал getattr(o, "city") o.city дегенмен бірдей. Django-дағы rating__gte=4.5 сияқты синтаксис кілтті __ бойынша бөліп, өріс пен операторды алады.

Migrations

Модельге жаңа өріс қостыңыз (phone). Дерекқордағы кесте өздігінен өзгермейді. Migration деп схеманың нұсқаланған өзгерісін айтады: 0003_add_phone.py файлы ALTER TABLE cafe ADD COLUMN phone орындайды. Migration файлдары git-те сақталады, барлық орта (ноутбук, тест, production) оларды бір ретпен қолданады. Құралдар: Alembic, python manage.py migrate.

N+1 мәселесі

orders = Order.objects.all()           # 1 сұрау
for o in orders:
    print(o.customer.name)             # әр тапсырысқа +1 сұрау!

100 тапсырыс болса, 101 сұрау кетеді. Әр сұрау желі арқылы 2 мс болса да, бет 200 мс кешігеді. Шешім: байланысты деректі бір сұраумен алдын ала алу. SQL-де JOIN немесе WHERE id IN (...), Django-да select_related("customer") / prefetch_related, SQLAlchemy-де joinedload.

Жиі қателер

  • ORM-ды «SQL білу қажет емес» деп ойлау: баяу сұрауды табу үшін ол генерациялайтын SQL-ді оқи білу керек.
  • Цикл ішінде байланыс өрісіне жүгіну (N+1).
  • Migration-сыз модельді өзгерту: production-да «column does not exist» қатесі.
Dev ортада ORM-ның SQL логын қосыңыз (Django: connection.queries, SQLAlchemy: echo=True). Бір бет 50 сұрау жасап жатса, N+1 бар деген сөз.

7. Аутентификация және рұқсаттар: hash, token, рөлдер

Екі сұрақты ажыратыңыз. Authentication: сен кімсің? (логин мен құпия сөз). Authorization: саған не істеуге болады? (бариста тапсырысты көреді, бірақ мәзір бағасын өзгерте алмайды). Біріншісі сәтсіз болса 401, екіншісі сәтсіз болса 403.

Құпия сөзді ешқашан ашық сақтамаңыз

Дерекқор ұрланса, ашық құпия сөздер бірден басқа сайттарда қолданылады. Сондықтан сақтайтынымыз hash. Бірақ жай sha256(password) жеткіліксіз:

  • Бірдей құпия сөздің hash-ы бірдей, сондықтан дайын кестелермен (rainbow table) тез табылады. Шешімі: әр пайдаланушыға кездейсоқ salt (os.urandom(16)).
  • SHA-256 өте жылдам: видеокарта секундына миллиардтаған нұсқаны тексереді. Шешімі: hash-ты мыңдаған рет қайталау (key stretching).
import hashlib, hmac, os

salt = os.urandom(16)
stored = hashlib.pbkdf2_hmac("sha256", b"qwerty123", salt, 600_000)

def check(password, salt, stored):
    candidate = hashlib.pbkdf2_hmac("sha256", password.encode(), salt, 600_000)
    return hmac.compare_digest(candidate, stored)

PBKDF2 ішінде HMAC-ты қайта-қайта есептеп, нәтижелерді XOR арқылы біріктіреді. hmac.compare_digest салыстыруды тұрақты уақытта жасайды, сондықтан шабуылдаушы жауап уақытына қарап символдарды болжай алмайды. Production-да bcrypt немесе Argon2 кітапханалары да кең қолданылады. Браузердегі Python-да pbkdf2_hmac жоқ, сондықтан тапсырмада оны hmac арқылы өзіңіз жазасыз: бұл алгоритмді түсінудің ең жақсы жолы.

Session немесе token

SessionToken (мысалы, JWT)
Сервер не сақтайдыsession_id → user кестесіештеңе: token өзі қол қойылған
Клиент не жібередіCookie: sid=...Authorization: Bearer ...
Шығару (logout)жазбаны өшіру жеткіліктіқиын: мерзімі бітуін күту не қара тізім
Қайда ыңғайлыклассикалық сайтмобильді қосымша, микросервистер

Қол қойылған token

import base64, json
payload = {"user": 7, "role": "barista", "exp": 1767225600}
body = base64.urlsafe_b64encode(json.dumps(payload).encode()).decode().rstrip("=")
sig = hmac.new(b"server-secret", body.encode(), hashlib.sha256).hexdigest()
token = body + "." + sig

Token-ді кез келген адам оқи алады (base64 шифр емес!), бірақ өзгерте алмайды: role-ды admin-ге ауыстырса, қолтаңба сәйкес келмейді. Сондықтан token-ге құпия дерек салмаймыз, ал exp өрісімен мерзімін шектейміз. JWT дәл осылай құрылған, тек үш бөліктен тұрады: header, payload, signature.

Рөлдер мен рұқсаттар

ROLES = {"barista": {"orders:read"}, "manager": {"orders:read", "menu:edit"}}
def can(user, perm):
    return perm in ROLES.get(user["role"], set())

Кодта if role == "manager" деп жазудың орнына рұқсат атауын тексеріңіз: жаңа рөл қосқанда кодты өзгертпейсіз.

OAuth 2.0 (тек идея)

«Google арқылы кіру» батырмасы OAuth 2.0 authorization code ағымын қолданады:

  • Сайт пайдаланушыны Google-дың кіру бетіне жібереді, сұрайтын рұқсаттарын (scope: email, profile) көрсетеді.
  • Пайдаланушы келісім береді, Google оны сайтқа қысқа мерзімді code-пен қайтарады.
  • Сайттың сервері code-ты өз құпия кілтімен access token-ге (кейде refresh token-ге де) айырбастайды.
  • Сервер access token арқылы Google API-дан пайдаланушының email-ін алады.

Маңызды нәтиже: сайт пайдаланушының Google құпия сөзін ешқашан көрмейді.

Жиі қателер

  • == арқылы hash салыстыру, salt-сыз немесе жылдам hash.
  • Секрет кілтті кодқа жазып, git-ке салу (оны env айнымалыда сақтаңыз, 11-сабақ).
  • Тексерілмеген token payload-ына сену.
Аутентификацияны өзіңіз ойлап таппаңыз: production-да тексерілген кітапханаларды қолданыңыз. Бұл сабақтың мақсаты: олардың іште не істейтінін түсіну.

8. Тестілеу: unittest, test client, қате жолдары

Software Eng курсында assert және pytest арқылы функцияларды тексердіңіз. Backend-те тест тағы да маңызды: бір өзгеріс ондаған endpoint-ке әсер етеді, ал оларды қолмен curl арқылы тексеріп шығу мүмкін емес. Бұл сабақта стандартты кітапханадағы unittest-ті және HTTP-сіз «test client» идеясын үйренеміз.

unittest.TestCase

import unittest

def bus_fare(age, card=True):
    if age < 0:
        raise ValueError("жас теріс болмайды")
    if age < 7:
        return 0
    return 80 if card else 150

class FareTests(unittest.TestCase):
    def test_child_is_free(self):
        self.assertEqual(bus_fare(5), 0)

    def test_cash_is_more_expensive(self):
        self.assertGreater(bus_fare(30, card=False), bus_fare(30))

    def test_negative_age(self):
        with self.assertRaises(ValueError):
            bus_fare(-1)

Әр тест test_ деп басталатын әдіс. Жиі қолданылатын тексерістер: assertEqual, assertTrue, assertIn, assertIsNone, assertRaises. Терминалда python -m unittest немесе pytest (ол unittest тесттерін де іске қосады) жазасыз. Браузерде тесттерді кодпен іске қосамыз:

import io
suite = unittest.defaultTestLoader.loadTestsFromTestCase(FareTests)
result = unittest.TextTestRunner(stream=io.StringIO()).run(suite)
print(result.testsRun, result.wasSuccessful())   # 3 True

setUp: әр тестке таза орта

setUp әр тест әдісінің алдында шақырылады, tearDown одан кейін. Тесттер бір-біріне тәуелді болмауы керек: бір тест жасаған тапсырыс келесі тестке «мұра» болып қалса, тесттер ретіне қарай кездейсоқ құлайды. pytest-те бұл рөлді fixture атқарады.

Test client

Flask пен FastAPI-да TestClient бар: ол серверді іске қоспай, сұрауды тікелей қосымшаға береді. Біз оны өзіміз жазамыз: клиент body-ді JSON-ға айналдырып, app.handle шақырады да, жауапты ыңғайлы объектіге орайды.

import json
from dataclasses import dataclass

@dataclass
class Response:
    status: int
    json: object

class TestClient:
    def __init__(self, app):
        self.app = app
    def request(self, method, path, json_body=None):
        raw = "" if json_body is None else json.dumps(json_body)
        status, body = self.app.handle(method, path, raw)
        return Response(status, json.loads(body) if body else None)

class CafeApiTests(unittest.TestCase):
    def setUp(self):
        self.client = TestClient(make_app())     # әр тестке жаңа қосымша
    def test_unknown_cafe(self):
        r = self.client.request("GET", "/cafes/999")
        self.assertEqual(r.status, 404)

Қате жолдарын тестілеу

Жаңа әзірлеуші әдетте тек «бәрі жақсы» жағдайын тексереді. Бірақ bug-тардың көбі шетінде: бос body, бұзық JSON, жоқ id, рұқсатсыз пайдаланушы, шекаралық мән (0, 10, 11). Әр endpoint үшін кемінде: бір сәтті жағдай, бір валидация қатесі (400/422), бір «табылмады» (404).

Жақсы тест қандай?

  • Жылдам және детерминистік: желісіз, нақты уақытсыз, кездейсоқтықсыз (уақыт пен random-ды сырттан беріңіз).
  • Бір тест бір нәрсені тексереді, ал атауы соны айтады: test_order_with_zero_qty_returns_422.
  • Bug-ты ұстай алады: кодты әдейі бұзсаңыз, тест құлауы керек. Құламаса, тест ештеңені тексермейді.
Bug табылғанда, түзетпес бұрын оны қайталайтын тест жазыңыз. Тест құлайды, сіз түзетесіз, тест өтеді, ал бұл bug енді ешқашан білінбей қайтып келмейді.

9. Regular expressions: тексеру, іздеу, ауыстыру

Пайдаланушы телефонын +7 (701) 234-56-78, 87012345678 немесе +7 701 234 5678 деп жазады. Оның бәрін тексеріп, бір форматқа келтіру үшін regular expression (regex) ыңғайлы: мәтіндегі үлгіні сипаттайтын шағын тіл. Python-да ол re модулінде.

Негізгі белгілер

ҮлгіМағынасы
\d, \w, \sцифр; әріп, цифр немесе _; бос орын
.кез келген бір таңба (жаңа жолдан басқа)
[abc], [^0-9]тізімдегі бір таңба; цифр емес таңба
*, +, ?, {3}, {2,4}0+, 1+, 0 немесе 1, дәл 3, 2-ден 4-ке дейін
^, $жолдың басы, соңы
( ), (?P<name> ), (?: )топ; атаулы топ; ұстамайтын топ

Үлгіні әрқашан raw string етіп жазыңыз: r"\d+". Әйтпесе \b сияқты тізбектерді Python өзі түрлендіріп жібереді.

Негізгі функциялар

import re
re.match(r"\d+", "42 latte")        # басынан ғана іздейді → match '42'
re.search(r"\d+", "latte 42")       # кез келген жерден бірінші → '42'
re.fullmatch(r"\d{6}", "050000")    # бүкіл жол сәйкес келуі керек
re.findall(r"#(\d+)", "#12 және #305")   # ['12', '305']: топ болса, тек топ
re.sub(r"\s+", " ", "Абай   даңғылы  10")   # 'Абай даңғылы 10'

Тексеру (валидация) үшін fullmatch немесе ^...$ қолданыңыз. match(r"\d{6}", "0500001") сәтті өтеді, себебі ол тек басын қарайды.

Топтар

m = re.search(r"(?P<city>[А-Яа-яӘәҒғҚқҢңӨөҰұҮүҺһІі]+), (?P<zip>\d{6})", "Мекенжай: Атырау, 060011")
m.group("city"), m.group("zip")     # ('Атырау', '060011')
m.groupdict()                       # {'city': 'Атырау', 'zip': '060011'}

Қазақстандық телефон

def normalize_phone(text):
    digits = re.sub(r"[\s()\-]", "", text)          # бос орын, жақша, дефис алынады
    m = re.fullmatch(r"(?:\+7|8)(7\d{9})", digits)
    return "+7" + m.group(1) if m else None

normalize_phone("+7 (701) 234-56-78")   # '+77012345678'
normalize_phone("8 777 111 22 33")      # '+77771112233'
normalize_phone("+7 495 123 45 67")     # None: мобильді емес

URL path талдау

PATH = re.compile(r"^/api/v(?P<version>\d+)/(?P<resource>[a-z-]+)(?:/(?P<id>\d+))?/?$")
PATH.match("/api/v2/orders/15").groupdict()
# {'version': '2', 'resource': 'orders', 'id': '15'}

re.compile үлгіні бір рет дайындайды: бір үлгі мыңдаған сұрауда қолданылса, бұл ыңғайлы әрі оқуға жеңіл.

Жиі қателер

  • Валидацияда search немесе match қолданып, жолдың соңын тексермеу.
  • . белгісін экрандамау: r"mail.kz" үлгісі mailXkz-ке де сәйкес келеді, дұрысы r"mail\.kz".
  • Email-ді «мінсіз» regex-пен тексеруге тырысу. Қарапайым тексеріс жеткілікті, ал нағыз тексеріс растау хатын жіберу.
  • Greedy («ашкөз») .*: <.*> бірінші <-ден соңғы >-ге дейін бәрін алады. Жалқау нұсқасы: .*?.
Күрделі үлгіні re.VERBOSE жалауымен бірнеше жолға бөліп, түсініктеме жазуға болады. Үлгіні әрқашан бірнеше дұрыс және бірнеше қате мысалмен тексеріңіз.

10. Асинхрондылық, фондық тапсырмалар, кэш және rate limiting

Кофехана сервері бір сұрауда: дерекқордан мәзірді алады (20 мс), төлем жүйесіне сұрау жібереді (300 мс), SMS сервисіне хабар береді (150 мс). Процессор бұл уақыттың көбінде ештеңе істемей, жауап күтіп тұрады. Мұндай жұмыс I/O-bound деп аталады, ал оны тездетудің жолы күту кезінде басқа сұраумен айналысу.

Concurrency және parallelism

  • Concurrency: бір бариста үш тапсырысты алмастырып жасайды. Сүт қызып жатқанда кофе тартады. Бір уақытта бір ғана әрекет, бірақ күту босқа кетпейді.
  • Parallelism: үш бариста үш тапсырысты шынымен бір мезгілде жасайды (бірнеше процессор ядросы, бірнеше процесс).

I/O-bound жұмысқа concurrency жеткілікті (async, thread). CPU-bound жұмысқа (сурет өңдеу, үлкен есептеу) parallelism керек (бірнеше процесс).

async / await

async def fetch_menu(cafe_id):
    await db.query("SELECT ...")      # күту кезінде event loop басқа тапсырманы жүргізеді
    return ["latte", "raf"]

coro = fetch_menu(7)        # функция әлі орындалған жоқ! бұл coroutine объектісі
print(type(coro).__name__)  # coroutine
coro.close()

async def функциясын шақыру оны орындамайды, тек coroutine объектісін жасайды. Оны event loop жүргізеді: әр await-та coroutine «мен күтіп тұрмын» деп тоқтайды да, loop дайын тұрған келесі coroutine-ға ауысады. FastAPI, aiohttp, Django-ның async бөлігі осылай жұмыс істейді.

Генераторлармен өз event loop-ыңыз

Coroutine идеясы генераторлардан шыққан: yield де функцияны тоқтатып, басқарушыға береді. Мына шағын scheduler әр тапсырманың «қанша уақыт ұйықтағысы келетінін» yield арқылы алып, жалған сағатпен (нақты күтусіз) ең ерте оянатын тапсырманы жүргізеді:

import heapq

def order(name, steps):
    for step, seconds in steps:
        print(f"{name}: {step}")
        yield seconds                     # «await sleep(seconds)»

def run(tasks):
    clock, queue = 0, [(0, i, t) for i, t in enumerate(tasks)]
    heapq.heapify(queue)
    while queue:
        clock, i, task = heapq.heappop(queue)
        try:
            delay = next(task)
            heapq.heappush(queue, (clock + delay, i, task))
        except StopIteration:
            print(f"t={clock}: тапсырма {i} бітті")

run([order("Латте", [("сүт қыздыру", 3), ("құю", 1)]),
     order("Американо", [("кофе тарту", 1), ("су қосу", 1)])])

Нағыз asyncio-да да солай: тапсырмалар кезегі, уақыт бойынша heap және «дайын» тапсырмаларды кезекпен жүргізу.

Фондық тапсырмалар: Celery, RabbitMQ

Кейбір жұмыс сұрау ішінде орындалмауы керек: чекті PDF-ке айналдыру, 10 000 клиентке хабар жіберу, түнгі есеп. Handler тапсырманы кезекке (broker: RabbitMQ немесе Redis) салып, бірден 202 Accepted қайтарады. Бөлек worker процестері (Celery, RQ) кезектен тапсырма алып, орындайды. Тапсырма сәтсіз болса, кейінірек қайталанады (retry), сондықтан оны идемпотентті етіп жазған жөн.

Кэш және rate limiting

Жиі сұралатын, сирек өзгеретін дерек (валюта бағамы, мәзір) кэштеледі: процесс ішінде functools.lru_cache, бірнеше сервер арасында Redis. Әр кэшке мерзім (TTL) керек. Rate limiting бір клиенттің сұрау санын шектейді (мысалы, минутына 60), артығына 429 Too Many Requests. Танымал алгоритм token bucket: себетте ең көбі capacity token бар, секунд сайын rate token қосылады, әр сұрау бір token жұмсайды.

Жиі қателер

  • Async функция ішінде блоктайтын кодты (time.sleep, синхронды дерекқор драйвері) шақыру: бүкіл loop тоқтайды.
  • await-ты ұмыту: coroutine жасалады, бірақ ешқашан орындалмайды.
  • Rate limiter-ді нақты time.time()-ға байлау: оны тестілеу қиын. Сағатты сырттан беріңіз.
Уақытқа тәуелді кодқа сағатты параметр ретінде беріңіз (clock=time.monotonic). Тестте оның орнына қолмен басқарылатын жалған сағат қоясыз да, «бір минут өтті» дегенді бір жолмен жасайсыз.

11. Деплой: Gunicorn, Nginx, Docker, CI/CD, env

Код ноутбукта жұмыс істейді. Енді оны мыңдаған пайдаланушы күні-түні қолдана алатын серверге шығару керек. Бұл деплой. Браузерде оны іске қоса алмаймыз, бірақ әр бөліктің рөлін түсініп алайық.

Virtualenv: еске салу

Software Eng курсында python -m venv .venv және requirements.txt-ті өттік. Серверде де дәл сол: нұсқалары бекітілген тәуелділіктер (flask==3.0.3), сонда production мен ноутбук бірдей кітапханаларды қолданады.

Сұрау серверге дейін қалай жетеді

Браузер ──HTTPS──▶ Nginx ──HTTP──▶ Gunicorn ──▶ сіздің Flask/Django қосымшаңыз
                    │                (4 worker процесі)
                    └── /static/ файлдарын өзі береді
  • Flask-тың app.run() тек әзірлеуге арналған: баяу және қауіпсіз емес.
  • Gunicorn (WSGI сервер) немесе Uvicorn (ASGI, async үшін): қосымшаның бірнеше worker процесін іске қосады. Бастапқы ереже: 2 × ядро саны + 1. Worker құласа, оны қайта көтереді.
  • Nginx (reverse proxy): алдыңғы есік. HTTPS сертификатын ұстайды, статикалық файлдарды береді, баяу клиенттерден қорғайды, жүктемені бірнеше серверге бөледі.
gunicorn --workers 4 --bind 0.0.0.0:8000 app:app

Docker

«Менің компьютерімде жұмыс істейді» мәселесін Docker шешеді: қосымша, Python нұсқасы және тәуелділіктер бір image-ке жиналады, ол кез келген серверде бірдей container болып іске қосылады.

# Dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["gunicorn", "--workers", "4", "--bind", "0.0.0.0:8000", "app:app"]

requirements.txt-ті кодтан бұрын көшіру маңызды: код өзгергенде Docker тәуелділіктер қабатын кэштен алады, build тез өтеді.

docker-compose

# docker-compose.yml
services:
  web:
    build: .
    ports: ["8000:8000"]
    env_file: .env
    depends_on: [db, redis]

      POSTGRES_PASSWORD: example

docker compose up бір командамен қосымшаны, PostgreSQL мен Redis-ті бірге көтереді. Жаңа әзірлеуші жобаны бірнеше минутта іске қосады.

Env айнымалылар

Құпия кілттер мен баптаулар кодта емес, ортада сақталады: os.environ["DATABASE_URL"]. Жергілікті ортада олар .env файлында тұрады, ал ол файл .gitignore-ға қосылады. Бір image dev, staging және production-да тек env арқылы ерекшеленеді.

Health check

GET /health endpoint-і «тірімін» деп 200 қайтарады. Docker, Kubernetes немесе load balancer оны бірнеше секунд сайын тексеріп, жауап бермеген container-ді қайта іске қосады. Кеңейтілген нұсқасы дерекқор мен Redis байланысын да тексеріп, бірі істемесе 503 қайтарады.

CI/CD: GitHub Actions

MLOps курсында CI workflow-ын көрдіңіз. Backend-те тізбек: push → тесттер мен linter (CI) → Docker image build → registry-ге push → серверге автоматты деплой (CD). Тест құласа, деплой болмайды.

Жиі қателер

  • .env-ті git-ке салу немесе DEBUG=True күйінде production-ға шығару.
  • Container ішінде деректі сақтау: container қайта жасалғанда жоғалады. Дерекқорға volume керек.
  • Health check-сіз деплой: «қосымша іске қосылды, бірақ жауап бермейді» деген жағдайды ешкім байқамайды.
Бір image, көп орта: кодты әр ортаға бөлек өзгертпеңіз. Айырмашылықтың бәрі env айнымалыларда болсын.

12. Мини жоба: URL қысқартқыш сервисі

Модульдің бәрін бір сервиске жинаймыз. «Tolqyn Link» деп аталатын URL қысқартқыш ұзын сілтемені https://tq.kz/q0U сияқты қысқа кодқа айналдырады, кодқа кірген адамды бастапқы мекенжайға бағыттайды және кліктерді санайды. Мұндай сервистерді жарнама, QR код және SMS тарату үшін маркетологтар күнде қолданады.

API кестесі

СұрауBodyЖауап
POST /links{"url": "...", "alias": "nauryz"} (alias міндетті емес)201 жаңа сілтеме; 200 бұл URL бұрын қысқартылған болса; 400 бұзық JSON; 422 қате URL/alias; 409 alias бос емес

Base62: санды қысқа кодқа

Әр сілтемеге өсетін id береміз, ал кодты id-ден жасаймыз. Ондық жүйеде 10 цифр бар, base62-де 62 таңба: 0-9, a-z, A-Z. Сонда 6 таңбалы код 626 ≈ 56 миллиард сілтемені сыйдырады.

ALPHABET = "0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ"

def encode(n):
    if n == 0:
        return "0"
    out = []
    while n:
        n, r = divmod(n, 62)     # соңғы «цифр» және қалғаны
        out.append(ALPHABET[r])
    return "".join(reversed(out))

encode(61)       # 'Z'
encode(62)       # '10'
encode(100000)   # 'q0U'

Кері түрлендіру Горнер схемасымен: n = n * 62 + ALPHABET.index(ch). id 1-ден басталса, алғашқы кодтар өте қысқа және болжамды болады, сондықтан біз 100000-нан бастаймыз. Нағыз сервистерде id-ді араластырып (немесе кездейсоқ код жасап) кодтарды тізбектеп болжауды қиындатады.

Сервис логикасы

        # 4) alias бос емес → 409
        # 5) код жасау, сақтау → 201
    def resolve(self, code):

Деректерді сөздікте сақтаймыз: self.links[code] = {"url": ..., "clicks": 0}. Нағыз жобада бұл PostgreSQL кестесі болар еді (6-сабақтағы repository), ал кліктерді жылдамырақ санау үшін Redis-тегі INCR командасы қолданылады.

Неге 302, 301 емес?

301 Moved Permanently жауабын браузер кэштейді: келесі жолы ол серверге сұрамай-ақ тікелей бастапқы сайтқа барады, сонда клік саналмайды. 302 Found (немесе 307) уақытша бағыттау, браузер әр жолы серверден сұрайды.

Тесттер

Сервисті әр бөлігі үшін тестпен қорғаймыз: base62 үшін «encode, сосын decode бастапқы санды береді» (round-trip), create үшін сәтті және қате жолдар, resolve үшін клік санағы. 8-сабақтағыдай, тест әдейі бұзылған нұсқада құлауы керек.

Жиі қателер

  • javascript:alert(1) сияқты URL-ды қабылдау: тек http және https рұқсат етіңіз.
  • Alias пен автоматты кодтың соқтығысуы: пайдаланушы q0U alias-ын алса, генератор оны қайта бермеуі керек.
  • Stats endpoint-ін шақырғанда да кліктерді арттыру.
Келесі қадам ретінде өз нұсқаңызға 4-сабақтағы роутерді (POST /links, GET /<code>), 10-сабақтағы rate limiter-ді және 11-сабақтағы /health-ты қосыңыз. Сонда толық шағын backend шығады.

13. Модуль емтиханы: Python Backend

Емтихан бүкіл модульді қамтиды: HTTP сұрауды талдау, роутинг, валидация мен status code-тар, қол қойылған token, regex, rate limiting және ORM ойлауы. Өту үшін ұпайдың кемінде 75%-ын жинау керек.

  • Функция мен класс атаулары дәл берілгендей болуы керек. Handler-лер (status, body) жұбын қайтарады.
  • Алдымен шағын мысалмен print арқылы тексеріп алыңыз, сосын «Тексеру» батырмасын басыңыз.
  • Есіңізде болсын: 400 оқылмайтын сұрау, 422 ережеге сай емес мән, 401 кім екені белгісіз, 403 рұқсат жоқ, 404 жоқ, 405 метод жоқ.
